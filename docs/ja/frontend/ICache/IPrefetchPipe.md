# IPrefetchPipeサブモジュール ドキュメント

IPrefetchPipeは、プリフェッチリクエストをフィルタリングする役割を担う、2ステージパイプラインとして設計されたプリフェッチパイプラインです。

![IPrefetchPipe構造](../figure/ICache/IPrefetchPipe/iprefetchpipe_structure.png)

## S0パイプラインステージ

S0パイプラインステージでは、FTQ/バックエンドからプリフェッチリクエストを受け取り、MetaArrayとITLBに読み取りリクエストを送信します。

## S1パイプラインステージ

まず、ITLBから応答を受け取ってpaddrを取得し、それをMetaArrayから返されたタグと比較してヒット情報を決定します。メタデータ（ヒット情報 `waymask`、ITLB情報 `paddr`/`af`/`pf`）はWayLookupに書き込まれます。同時に、PMPチェックが実行され、その結果は次のパイプラインステージのために登録されます。

ステートマシンによって制御されます。

- 初期状態は`idle`です。新しいリクエストがS1パイプラインステージに入ると、まずITLBがミッシングかどうかをチェックします。ミッシングの場合は`itlbResend`に入り、ITLBがヒットしたがヒット情報がWayLookupにエンキューされていない場合は`enqWay`に入り、ITLBがヒットしてWayLookupがエンキューされたがS2リクエストが完全に処理されていない場合は`enterS2`に入ります。
- `itlbResend`状態では、ITLBに読み取りリクエストを再送し、ITLBポートを占有します（これにより、新しいプリフェッチリクエストがS0パイプラインステージに入るのをブロックします）。リフィルが完了するまで待ちます。リフィルが完了したサイクルで、MetaArrayに別の読み取りリクエストを送信します。リフィル中に新しい書き込みが発生する可能性があります。MetaArrayがビジー（MSHRによって書き込み中）の場合、`metaResend`に遷移します。それ以外の場合は、`enqWay`に進みます。
- `metaResend`状態では、MetaArrayに読み取りリクエストを再送します。送信が成功すると、`enqWay`に入ります。
- `enqWay`状態では、メタデータをWayLookupにエンキューしようとします。WayLookupキューが満杯の場合、エンキューが成功するまでブロックします。さらに、MSHRで新しい書き込みが発生した場合、書き込まれた情報とヒット情報の間の競合を防ぐためにエンキューが禁止され、ヒット情報の更新が必要になります。WayLookupへのエンキューが成功した場合、S2がアイドルであれば直接`idle`に戻ります。それ以外の場合は`enterS2`に入ります。
  - 現在のリクエストがソフトウェアプリフェッチの場合、このリクエストはMainPipe/IFUに入る必要も実行される必要もないため、WayLookupへのエンキューは試みられません。
- `enterS2`状態では、リクエストを次のパイプラインステージに流そうとします。流れた後、`idle`に戻ります。

## S2パイプラインステージ

リクエストのヒット結果、ITLB例外、およびPMP例外を統合して、プリフェッチが必要かどうかを判断します。プリフェッチは例外が存在しない場合にのみ実行されます。同じ予測ブロックが2つのキャッシュラインに対応する可能性があるため、リクエストはアービタを介して順次MissUnitに送信されます。

## ヒット情報の更新 {#sec:IPrefetchPipe-hit-update}

S1パイプラインステージでヒット情報を取得した後、ヒット情報が実際にMainPipeで使用されるまでには2つのステージがあります。IPrefetchPipeでWayLookupにエンキューされるのを待つステージと、WayLookupでデキューされるのを待つステージです。この待機期間中に、MSHRによるMeta/DataArrayの更新が発生する可能性があるため、MSHRの応答を監視する必要があり、2つのシナリオに分かれます。

1. MetaArrayでミスし、MSHRが対応するキャッシュラインをSRAMに書き込んだことを監視した場合、ヒットステータスをヒットに更新する必要があります。
2. リクエストはすでにMetaArrayでヒットしていますが、同じ場所で別のキャッシュラインの書き込みが発生し、元のデータが上書きされたことを検出した場合、ヒット情報をミス状態に更新する必要があります。

更新ロジックの遅延がDataArrayのアクセスパスに導入されるのを防ぐため、MSHRで新しい書き込みが発生した場合はWayLookupへのエンキューが禁止され、次のサイクルでエンキューされます。
