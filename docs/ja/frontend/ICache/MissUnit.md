# MissUnitサブモジュール ドキュメント

MissUnitは、ICacheのミスリクエストを処理し、MSHRを介して管理し、Tilelinkバスを介してL2キャッシュと対話し、MetaArrayおよびDataArrayへの書き込みリクエストの送信、およびMainPipeへの応答の送信を担当します。

![MissUnit構造](../figure/ICache/MissUnit/missunit_structure.png)

## MSHR管理

MissUnitは、フェッチリクエストとプリフェッチリクエストをMSHRを介して別々に管理します。フラッシュ中にフェッチMSHRが完全に解放されることを保証するため、フェッチMSHRの数は4に、プリフェッチMSHRは10に設定されています。データとアドレスを分離した設計が使用され、すべてのMSHRがデータレジスタのセットを共有し、MSHRにはアドレス情報のみを格納します。

## リクエストのエンキュー

MissUnitは、MainPipeからフェッチリクエストを、IPrfetchPipeからプリフェッチリクエストを受け取ります。フェッチリクエストはfetchMSHRにのみ割り当て可能で、プリフェッチリクエストはprefetchMSHRにのみ割り当て可能で、エンキュー中にはインデックスの小さい順の割り当て戦略が使用されます。同時に、エンキュー中にMSHRがクエリされます。リクエストがMSHRに既に存在する場合、それは破棄され、外部インターフェースは発火したように見えますが、リクエストはMSHRにエンキューされません。エンキュー中に、waymaskの書き込みリクエストがReplacerに送信されます。

## acquire

L2へのバスがアイドル状態のとき、MSHRエントリが処理対象として選択されます。fetchMSHRはprefetchMSHRよりも優先度が高く、処理するfetchMSHRがない場合にのみprefetchMSHRが処理されます。fetchMSHRについては、同時に処理するリクエストが最大2つであり、両方とも完了してから次に進む必要があるため、fetchMSHR間の優先度はそれほど重要ではありません。prefetchMSHRについては、プリフェッチリクエストの時間的順序を考慮して、先着順の優先度戦略が採用されます。FIFOがエンキュー順を記録し、この順序に従って処理が行われます。

## grant

ステートマシンを介してTilelinkのDチャネルと対話します。L2への帯域幅は32バイトで、2回の送信が必要であり、異なるリクエストはインターリーブしないため、データを格納するために必要なレジスタは1セットのみです。送信が完了すると、送信IDに基づいて対応するMSHRが選択され、アドレスやマスクなどの情報がMSHRから読み取られます。関連情報はSRAMに書き込まれ、MSHRは解放されます。
