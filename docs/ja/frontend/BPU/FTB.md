# BPUサブモジュール FTB

## 機能概要

FTBはFTBエントリを一時的に保存し、後続の高度な予測器に対して、より正確な分岐命令の位置や種類などの情報を提供します。FTBモジュール内には、FTBエントリの実際の保存を担当するFTBBankモジュールがあり、マルチポートSRAMをメモリとして利用しています。

### リクエスト受信

ステージ0で、FTBモジュールは内部のFTBBankに読み出しリクエストを送信します。リクエストのPC値はs0から渡されたPCです。

### データ読み出しと返却

リクエストを送信した次のクロックサイクル、つまり予測器のステージ1で、FTB SRAMから読み出されたマルチウェイ信号が一時的に保存されます。

次のサイクル、つまり予測器のステージ2で、一時データから各ウェイのタグと実際のリクエストタグのマッチングに基づいてヒット信号が生成され、ヒットした場合にはヒットしたFTBデータが選択されます。ヒットリクエストがあった場合、戻り値は選択されたFTBエントリとヒットしたウェイ情報です。ヒットしなかった場合、出力データは無意味です。タグはPCの29ビットから10ビットに対応します。

FTBBankモジュールから読み出されたデータは、2ステージの予測結果として、同じサイクル内で組み合わせロジックを介して後続の予測器に渡されます。さらに、この読み出し結果はFTBモジュール内に一時的に保存され、3ステージで再び組み合わせロジックを介して後続の予測器に予測結果として渡されます。FTBがヒットした場合、読み出されたヒットウェイ番号もメタ情報として、ヒット情報やサイクルカウントと共にs3ステージで後続のFTQモジュールに渡されます。

さらに、FTBエントリに「always taken」フラグがある場合、ステージ2の予測結果の対応するbr_taken_maskもこのモジュール内でハイに設定されます。

### データ更新

更新リクエストを受信すると、FTBモジュールはメタ情報がヒットを示しているかどうかに基づいて更新タイミングを決定します。メタがヒットを示している場合、更新は現在のサイクルで即座に実行されます。そうでない場合は、FTBから既存の結果を読み出すために2サイクル待ってから更新を進める必要があります。

FTBBank内では、更新リクエストが存在する場合、モジュールの動作も即時更新と遅延更新で異なります。即時更新の場合、FTBBank内のSRAM書き込みチャネルがアクティブになり、与えられた情報で書き込みが完了します。遅延更新の場合、FTBBankはまず通常の予測読み出しリクエストよりも優先度の高い更新のための読み出しリクエストを受け取り、次のサイクルでデータを読み出し、与えられたアドレスにヒットしたウェイエンコーディングを選択して外部のFTBモジュールに渡します。このサイクルでヒットがなかった場合、次のサイクルで割り当てられたウェイに書き込む必要があります。ウェイ選択ルールは次のとおりです。すべてのウェイが満杯の場合、置換アルゴリズム（ここでは疑似LRU、詳細はICacheのドキュメントを参照）を使用して置換するウェイを選択します。そうでない場合は、空のウェイを選択します。

### SRAM仕様

- シングルバンク、512セット、4ウェイ
- シングルポートSRAMを使用、読み出しホールドなし、パワーオンリセットあり
- 20ビットタグ、60ビットFTBエントリ

**FTBエントリ**

- 1ビット valid
- 20ビット brスロット（4ビットオフセット、12ビット下位、2ビットtarStat、1ビット共有、1ビットvalid）
- 28ビット tailスロット（4ビットオフセット、20ビット下位、2ビットtarStat、1ビット共有、1ビットvalid）
- 4ビット pftAddr
- 1ビット carry
- 1ビット isCall
- 1ビット isRet
- 1ビット isJalr
- 末尾ビットはRVI callの可能性あり
- 2ビット always taken

### 機能概要

上述のように、FTBBankは主にFTBエントリを保存し、SRAMモジュールの単純なラッパーとして機能します。

## FTBエントリの生成条件の概要

FTBはBPUの中核です。BPUの他の予測コンポーネントが行う予測はすべて、FTBが提供する情報に依存します。FTBは、予測ブロック内の分岐命令の情報を提供するだけでなく、予測ブロックの終了アドレスも提供します。FTBにとって、FTBエントリの生成戦略は非常に重要です。南湖アーキテクチャは、元の論文1を基に、この論文2の考え方を組み合わせて現在の戦略を形成しました。FTBエントリの開始アドレスを `start`、終了アドレスを `end` とすると、具体的な戦略は以下のようになります。
