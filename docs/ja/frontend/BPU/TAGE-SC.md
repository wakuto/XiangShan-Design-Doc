# BPUサブモジュール TAGE-SC

## 機能

TAGE-SCは、南湖アーキテクチャにおける条件分岐の主要な予測器であり、高精度予測器（APD）に分類されます。TAGEは、さまざまな履歴長を持つ複数の予測テーブルを活用して、非常に長い分岐履歴情報を利用します。一方、SCは統計的補正器として機能します。

TAGEは、ベース予測テーブルと複数の履歴テーブルで構成されています。ベース予測テーブルはPCによってインデックス付けされ、履歴テーブルはPCと特定の長さの分岐履歴のフォールドされたバージョンのXOR結果によってインデックス付けされます。異なる履歴テーブルは、さまざまな長さの分岐履歴を使用します。予測中、タグはPCと各履歴テーブルに対応する分岐履歴の別のフォールドされたバージョンをXORすることによっても計算され、テーブルから読み取られたタグと照合されます。一致は、そのテーブルのヒットを示します。最終結果は、最も長い一致履歴長を持つ履歴テーブルからの予測に依存します。

SCがTAGEが高い誤予測の確率を持っていると判断した場合、最終的な予測結果を反転させます。

南湖アーキテクチャでは、各予測は同時に最大2つの条件分岐命令を予測できます。TAGEのさまざまな履歴テーブルにアクセスする場合、予測ブロックの開始アドレスがPCとして使用され、2つの予測結果が同時にフェッチされ、両方とも同じ分岐履歴を使用します。

### TAGE: 設計思想

ハイブリッド予測器として、TAGEの利点は、特定の分岐命令に対して異なる長さの分岐履歴シーケンスに基づいて同時に分岐予測を実行できる能力にあります。さまざまな履歴シーケンスの下での分岐命令の精度を評価し、最終的な分岐予測基準として最も高い履歴精度を持つものを選択します。

従来のハイブリッド予測器と比較して、TAGEは予測精度を大幅に向上させる2つの新しい設計機能を組み込んでいます。

- **タグデータの追加**: 予測テーブルの各エントリにタグデータを追加しました。従来の優先分岐予測器では、分岐履歴と現在の分岐命令のPC値のみが予測テーブルからのフェッチの基準としてよく使用されます。これにより、複数の異なる分岐命令が同じ予測テーブルエントリを指す（エイリアシング）可能性があり、特にハイブリッド予測器の短い履歴長部分の予測精度に影響を与えます。したがって、TAGEの設計では、部分的なタギング方法により、現在の命令と予測テーブル内の実際のエントリがよりよく一致し、このような状況の発生を大幅に削減します。
- **幾何学的に変化する分岐履歴長**: 異なる予測テーブルをインデックスするために幾何学的に変化する分岐履歴長を使用し、分岐予測中のテーブルエントリ選択の粒度を大幅に向上させます。さらに、各テーブルエントリには有用性カウンタが含まれており、分岐予測精度への貢献度を記録します。この設計により、さまざまな分岐命令が最終予測のために最も正確な分岐履歴長によってインデックス付けされる可能性が高くなります。

これらの2つの設計機能により、TAGE予測器は、選択された分岐履歴長が短すぎて複数の異なる命令が同じテーブルエントリにマッピングされることによる情報有効性の低下や、分岐履歴長が長すぎて効果を発揮するまでに非常に長い時間がかかるという問題の両方を回避できます。したがって、TAGEは非常に広範囲の分岐履歴長を利用でき、さまざまなコードコンテキストでの分岐命令の予測に適しています。

### TAGE: ハードウェア実装

TAGEは、高精度の条件分岐方向予測器です。さまざまな長さの分岐履歴と現在のPC値を使用して、複数のSRAMテーブルをアドレス指定します。複数のテーブルでヒットが発生した場合、最も長い一致履歴を持つエントリからの予測結果が最終結果として優先されます。

![TAGEの原理](../figure/BPU/TAGE-SC/principle.png)

TAGEの構造概略図は上の図に示されており、ベースライン予測器T0と4つのタグ付き予測テーブルT1-T4を備えています。ベースライン予測器とタグ付き予測テーブルに関する基本情報は、以下の表に示されています。

| **予測器** | **タグ付き** | **機能** | **エントリ構成** | **項目数** |
|---|---|---|---|---|
| ベースライン予測器 T0 | いいえ | 4つのローカルタグ予測テーブルのタグが一致しない場合に予測結果を提供するために使用されます。 | ctrは2ビット（最上位ビットが予測結果を提供：1はジャンプ、0はジャンプなし）。 | セット2048ウェイ2 |
| 予測テーブル T1-T4 | はい | タグの一致がある場合、最も長い履歴を持つものが予測結果を提供するために選択されます。 | valid 1ビット、tag 8ビット、sctr 3ビット（最上位ビットが予測結果を示す：1はtaken、0はnot taken）、us: 1ビット（有用性カウンタ） | T1-T4はそれぞれ4096エントリ。 |

注：上の表の「ウェイ」は、ChiselのSRAMTemplateクラスのパラメータ名です。このパラメータの値は、SRAMに同じタイプのデータがいくつ格納されているかを示し、必ずしもタグマッチングを必要とする従来の「ウェイ」の意味を表すわけではありません。T0に2つのウェイがあるのは、予測ブロックに最大2つの分岐命令が含まれる可能性があり、異なるウェイがブロック内の2つの異なる分岐命令を予測するために使用されるためです。

各予測ブロックの2つのジャンプ命令の予測内容は、別々に保存および更新されます。タグ付き予測テーブルT1-T4の4096エントリは、予測ブロックごとに最大2つの分岐のために2つのバンクに均等に分割され、各バンクには2048エントリが含まれます。したがって、テーブルT1-T4のインデックスはわずか11ビットで、log2(テーブルエントリ数/2)として計算されます。同じ予測ブロック内の2つの分岐命令は同じインデックスを共有しますが、異なるバンクにアクセスするため、両方のバンクから同時に予測結果を読み取る際に、一方がヒットし、もう一方がミスする可能性があります。

TAGEスタイルの予測器の各予測テーブルには、特定の履歴長があります。非常に長いグローバル分岐履歴テーブルをPCとXORして予測テーブルのインデックス付けやタグマッチングを行えるようにするため、非常に長い分岐履歴シーケンスを多くのセグメントに分割し、それらをすべてXORする必要があります。各セグメントの長さは、通常、履歴テーブルの深さの対数に等しくなります。XORの回数が多いため、予測パス上の多段XORの遅延を避けるために、フォールディング後の履歴を直接保存します。

各予測テーブルに対応するフォールディング分岐履歴は3つあり、1つは予測テーブルのインデックス用、2つはタグマッチング用です。BPUモジュールでは、256ビットのグローバル分岐履歴ghvが維持され、TAGEの4つのタグ付き予測テーブルそれぞれに独自のフォールディング分岐履歴が維持されます。具体的な設定は以下の表（TageTableInfosを参照）に示されています。ここで、ghvは循環キューであり、「下位」nビットはptrが指す位置から数えた下位ビットを指します。

| **履歴** | **インデックスフォールディング分岐履歴長** | **タグフォールディング分岐履歴1長** | **タグフォールディング分岐履歴2長** | **設計原理** |
|---|---|---|---|---|
| グローバル分岐履歴 ghv | 256ビット（非フォールディング） | なし | なし | 各ビットは対応する分岐がジャンプしたかどうかを表す |
| T1対応フォールディング分岐履歴 | 8ビット | 8ビット | 7ビット | ghvのptrから始まる下位8ビットをフォールディングしてXOR |
| T2対応フォールディング分岐履歴 | 11ビット | 8ビット | 7ビット | ghvのptrから始まる下位13ビットをフォールディングしてXOR |
| T3対応フォールディング分岐履歴 | 11ビット | 8ビット | 7ビット | ghvのptrから始まる下位32ビットをフォールディングしてXOR |
| T4対応フォールディング分岐履歴 | 11ビット | 8ビット | 7ビット | ghvのptrから始まる下位119ビットをフォールディングしてXOR |

![フォールディング履歴の実際の実装](../figure/BPU/TAGE-SC/folded_history.png)

上の図に示すように、タイミングを考慮して、フォールディング分岐履歴の具体的な実装方法は、設計原理のフォールディングではなく、フォールディング前の分岐履歴の最も古いビット（図のh[12]に対応）と最新のビット（図のh[0]に対応）を対応する位置（図のc[1]とc[4]に対応）にXORし、シフト操作（図のc[0]とc[2]に変わる）を行うだけです。擬似コードは以下のようになります。

```
c[0] <= c[4] ^ h[0];
c[1] <= c[0];
c[2] <= c[1] ^ h[12];
c[3] <= c[2];
c[4] <= c[3];
```

分岐履歴テーブルは、バックエンドのコミット後にのみ更新されるわけではありません。s1からs3の各中間ステージでも更新される可能性があり、更新時にはポインタと値が更新されます。s1からs3で新しい結果が生成された場合、ポインタが復元され、新しい値が更新されます。しかし、予測に誤りがない場合は、（すでに更新されているため）変更されません。

注：TAGEのフォールディング分岐履歴の具体的な設定表からわかるように、タグフォールディング分岐履歴は2つあります。どちらも同じフォールディングアルゴリズムを使用していますが、違いはフォールディング長が異なる点です。T1-T4のタグフォールディング分岐履歴1はすべて8ビットですが、タグフォールディング分岐履歴2はすべて7ビットです。

### TAGE: 予測タイミング

予測を行うたびに、まず各タグ付き予測テーブルでPC値とそれぞれの分岐履歴を使用して2つの異なるハッシュ関数計算（以下の表を参照）が行われます。計算結果は、それぞれその演算の最終タグの計算と予測テーブルのインデックス付けに使用されます。

| | 計算方法 |
|---|---|
| インデックス | (インデックスフォールディング分岐履歴) ^ ((pc>>1)の下位ビット) |
| タグ | (タグフォールディング分岐履歴1) ^ (タグフォールディング分岐履歴2<<1) ^ ((pc>>1)の下位ビット) |

T1-T4でインデックスによって得られたvalidが1で、かつタグが計算されたタグハッシュ関数の結果と一致する場合、その予測テーブルで与えられたpredの最上位ビットが最終的な分岐予測シーケンスに追加されます。最終的に、多段MUXを介して、すべてのタグが一致した分岐予測の中から最も長い履歴長を持つものが最終的な予測結果として選択されます。

T1-T4に一致がない場合、T0が最終的な予測結果として採用されます。T0のインデックス方法は、PCの下位11ビットを直接使用してインデックス付けすることです。

TAGEには2サイクルの遅延が必要です。

- 0サイクル目：SRAMアドレッシング用のインデックスを生成。インデックスの生成プロセスは、フォールディングされた履歴とPCをXORすることです。フォールディングされた履歴の管理はITTAGEやTAGEの内部ではなく、BPU内で行われます。
- 1サイクル目：結果を読み出す。
- 2サイクル目：予測結果を出力する。

### TAGE: 予測器のトレーニング

まず、タグマッチを生成したすべての予測テーブルの中で最も長い履歴長を必要とするものを**プロバイダ**と定義し、タグマッチを生成した他の予測テーブル（存在する場合）を**altpred**と呼びます。

TAGEテーブルのエントリには**usefulness**フィールドが含まれています。プロバイダが正しく予測し、altpredが誤って予測した場合、プロバイダのusefulnessが1に設定されます。これは、そのエントリが有用であることを示し、トレーニング時の割り当てアルゴリズムによって空きエントリとして割り当てられることはありません。プロバイダが生成した予測が正しいと証明され、かつその時のプロバイダとaltpredの予測結果が異なる場合、プロバイダのusefulnessフィールドが設定されます。

分岐命令が実際に分岐する場合、対応するプロバイダテーブルエントリのctrカウンタがインクリメントされます。分岐命令が実際には分岐しない場合、対応するプロバイダテーブルエントリのctrカウンタがデクリメントされます。

誤予測によりTAGEテーブルエントリを更新する必要があり、かつ誤予測が正しいプロバイダを破棄してaltpredを使用したことによるものでない場合、エントリを追加する必要があることを示します。ただし、この時点で実際にエントリを追加できるとは限りません。プロバイダが由来する予測テーブルが、必要な履歴長が最も長い予測テーブルではないという条件も満たす必要があります。その場合、エントリ追加操作が実行されます。

ここでは、プロバイダが由来する予測テーブルが必要な履歴長が最も長い予測テーブルではないかどうかを判断する例を論理的に示します。

s1_providers(i)は、予測ブロック内のi番目の分岐のプロバイダに対応する予測テーブルの番号を表します。プロバイダが予測テーブルT2にあると仮定すると、LowerMask(UIntToOH(s1_providers(i)), TageNTables)は0b0011になります。s1_provideds(i)は、予測ブロック内のi番目の分岐のプロバイダがT1〜T4にあるかどうかを表します。先ほどの仮定に基づくと、Fill(TageNTables, s1_provideds(i).asUInt)は0b1111になります。この2つをANDすると、結果は0b0011になります。これを反転すると0b1100になり、T3、T4がプロバイダよりも長い履歴長を持つ予測テーブルであることがわかります。
