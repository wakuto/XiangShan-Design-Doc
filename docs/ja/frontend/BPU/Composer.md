# BPU サブモジュール: Composer

## 機能概要

Composerは、複数の予測器を組み合わせるためのモジュールです。南湖アーキテクチャでは、uFTB、FTB、TAGE-SC、ITTAGE、RASの5つの予測器を統合し、それらを3ステージのパイプライン化されたカバレッジ予測器として抽象化します。Composer内の各予測器は、カスタムレジスタsbpctlに書き込むことで有効/無効を切り替えることができ、オンデマンドで使用できます。外部からのリダイレクトを検出すると、Composerはリダイレクト要求を各予測器に転送し、投機的に更新された要素を回復します。予測ブロック内のすべての命令がコミットされた後、Composer内の予測器はトレーニングを受けます。最終的に、Composerは3ステージの予測結果をPredictorに出力します。

3ステージBPUパイプラインの内部リダイレクト中、予測エラーが発生した場合、分岐履歴やRASなどの投機的に更新された状態のみが復元されます。他の予測器の更新はコミット後に行われます。

予測器がフラッシュされず、パイプラインのみがリフレッシュされた場合、同じ場所で再び誤って予測されるのではないでしょうか？パイプラインをリフレッシュすると、修正されたパスから予測が開始されます。後続のパスが同じ場所を再訪した場合、再び同じ結果を予測する可能性があります。ただし、分岐履歴が異なるため、TAGEなどの予測器は異なるエントリをインデックスする可能性があります。

実行中にターゲットアドレスエラーが検出された場合、すぐにリダイレクトは開始されません。代わりに、リダイレクトは命令のコミットまで一様に延期されます。この設計の一つの理由は、誤予測のリダイレクトは誤ったパス上で発生し、実行結果も誤っている可能性があるためです。このような状況でトレーニングを行うと、予測器を汚染する可能性があります。

### 開始PCの設定

ComposerのIOインターフェースio_reset_vectorは、開始PCの設定を可能にします。目的の開始PCをこのIOに渡すだけで済みます。

### 予測器との接続

Composerは、uFTB、FTB、TAGE-SC、ITTAGE、RASの5つの予測器を接続します。3つの分岐予測器パイプラインステージがあり、各予測器は固定のレイテンシを持っているため（指定されたステージまでに予測を完了する）、Composerは単に対応するパイプラインステージで対応する予測器の結果を出力するだけです。

メタとは、予測時に予測器が使用するデータであり、トレーニングのための更新時に取得されます。すべての予測器がComposerによって統合され、共通のメタインターフェースを介して外部と対話するため、これらはすべてメタと呼ばれます。

### 予測器の有効/無効化

Zicsr命令を通じて、カスタムCSRであるsbpctlを読み書きすることで、Composer内のさまざまな予測器の有効化を制御できます。sbpctl[6:0]は、{LOOP, RAS, SC, TAGE, BIM, BTB, uFTB}の7つの予測器の有効化を表します。ハイレベルは有効化を示し、ローレベルは無効化を示します。具体的には、spbctl CSRの値は、ComposerのIOインターフェースio_ctrl_*を介して各予測器に渡され、各予測器が有効化の実装を担当します。

### リダイレクトの回復

Composerは、io_s2_redirect、io_s3_redirect、io_redirect_*などのIOポートを介してリダイレクト要求を受信します。これらの要求は、RASスタックのトップアイテムなど、投機的に更新された要素を回復するために、その予測器に送信されます。

### 予測器のトレーニング

Composerは、IOポートio_update_*を介してトレーニング信号を予測器に送信します。一般に、誤った実行パスによる予測器の内容の汚染を防ぐため、各予測器は予測ブロック内のすべての命令がコミットされた後にトレーニングされます。トレーニング内容は、自身の予測情報と、予測ブロック内の命令のデコードおよび実行結果から得られ、これらはFTQから読み出されてBPUに返送されます。予測情報は予測後にパックされてFTQに保存されます。命令のデコード結果はIFUのプリデコードモジュールから得られ、命令のフェッチ後にFTQに書き戻されます。実行結果はさまざまな実行ユニットから得られます。

## インターフェースタイミング

### 制御信号Ctrlインターフェースタイミング

![制御信号Ctrlインターフェースタイミング](../figure/BPU/Composer/port1.png)

上の図は、Composerモジュールの制御信号Ctrlインターフェースのタイミング例を示しています。io_ctrl信号は、Composerモジュールに入った後、1サイクル遅延されて内部のコンポーネントサブモジュールに渡されます。

### リダイレクトインターフェースタイミング

![リダイレクトインターフェースタイミング](../figure/BPU/Composer/port2.png)

上の図は、Composerモジュールのリダイレクト要求インターフェースを示しています。BPUがバックエンドからリダイレクト要求を受信した後、1サイクル遅延されてComposerに送信されるため、Composer内の予測器は対応する要求を1サイクル遅れて受信します。

### 分岐予測ブロックトレーニングインターフェースタイミング

![分岐予測ブロックトレーニングインターフェースタイミング](../figure/BPU/Composer/port3.png)

リダイレクトと同様に、タイミングを最適化するため、分岐予測ブロックトレーニングのupdateインターフェースもBPU内部で1サイクル遅延されてComposerおよびその内部の各予測器に送信されます。
