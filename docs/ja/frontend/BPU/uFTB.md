# BPUサブモジュール uFTB

## 機能概要

uFTBはBPUのネクストライン予測器として機能し、プロセッサにバブルフリーの基本的な予測を提供して、次の投機的なPC値を継続的に生成します。

### uFTBリクエストの受信

ステージ0のリクエストが有効になるたびに、予測ブロックの開始PCの16ビットから1ビットまでを抽出してタグを生成し、モジュール内の完全連想uFTBに送信してFTBエントリを読み取ります。FTBエントリの内容は前述のとおりです。uFTBの各バンクには、レジスタで実装された32個の完全連想エントリが含まれています。レジスタベースの実装のため、各エントリは、保存されたデータが有効かどうか、および保存されたタグが入力情報と一致するかどうかに基づいて、現在のサイクルでヒット信号と読み取られたFTBエントリデータを生成できます。ただし、このデータは現在のサイクルではなく、次のサイクルで使用されます。

### uFTBデータの読み取りと返却

次のサイクルで、uFTBメモリバンクはヒット信号と読み出しデータを返します。予測器はステージ1に入ります。このステージでは、返されたヒット信号から最大1つのヒットエントリが選択され、このヒットエントリを使用して予測結果が生成されます。完全な予測結果を生成するアルゴリズムは、後続のFTBモジュールで詳しく説明されています。ここで、uFTBには追加のカウンタメカニズムがあり、uFTBの各エントリは最大2つの分岐命令を持つことができ、それぞれに2ビットのカウンタが付いています。カウンタが1より大きい場合、またはFTBエントリのalways_takenフラグが有効な場合（後者のメカニズムはFTBモジュールにも存在します）、予測結果はジャンプになります。さらに、このステージのヒット信号と選択されたヒットウェイ番号は、この予測器のメタ情報として使用され、ステージ3で他の予測器と一緒に送信されるのを待ち、最終的な予測結果とともにFTQに保存されます。この予測器はステージ2および3で追加のアクションはありません。

### uFTBデータの更新

予測ブロックに対応するすべての命令がコミットされると、FTQからBPUへの更新チャネル（このモジュールに直接接続されています）には、命令コミット情報に基づいてFTQモジュールによって更新されたFTBエントリが含まれます。完全連想uFTBは完全にレジスタで構築されているため、書き込み操作は並列の読み取り操作に影響を与えず、入力された更新情報は常に適用されます。更新チャネルが有効な場合、現在のサイクルでは、入力された更新PC値を使用してタグを生成し、uFTB内の既存のエントリと照合して、一致信号と一致したウェイ信号を生成します。次のサイクルで、一致が存在する場合、一致したウェイの書き込み信号がアサートされます。それ以外の場合、疑似LRU置換アルゴリズムが置換するウェイを選択し、対応する書き込み信号がアサートされます。書き込まれるデータは更新されたFTBエントリです。

各分岐命令のカウンタのメンテナンスも、更新チャネルがアサートされたときに更新されます。更新チャネルがアサートされた次のサイクルで、更新されたFTBエントリ内の分岐命令とその前の命令のカウンタが更新されます。分岐が実行された場合、カウンタは1インクリメントされます。実行されなかった場合、1デクリメントされます。カウンタが飽和している場合（0またはすべて1）、現在の値が維持されます。

疑似LRUアルゴリズムもデータ更新を必要とし、2つのデータソースがあります。1つは予測時のヒットのウェイエンコーディング、もう1つはuFTB更新時に書き込まれるウェイエンコーディングです。どちらかが有効な場合、その情報を使用して疑似LRU状態が更新されます。同じサイクルで両方が有効な場合、組み合わせロジックを使用して両方の情報で状態を順次更新します。

### SRAM仕様

このモジュールは内部でSRAMを使用しませんが、多数のレジスタ連結構造が含まれており、以下にリストします。

このモジュールには32ウェイのデータが含まれており、それぞれが基本的な分岐方向予測のための2つの2ビット幅飽和カウンタ、60ビットのFTBエントリ（FTBモジュールと同じ意味、詳細はFTB SRAM仕様を参照）、16ビットのタグ、および1ビットのウェイ有効信号で構成されています。
