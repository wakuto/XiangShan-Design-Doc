## 機能

### 全体機能

データパスはパイプラインにおいて、発行の後、実行ユニットに入る前に位置します。データパスは整数、浮動小数点、ベクトル、メモリアクセスの発行キューの各出口から命令を受け取ります。これらの各出口は実行ユニットのExeUnitと1対1で対応します。データパスは各命令のためにレジスタファイルを読み出し、即値を構築し、ExeUnitに入る前に最終的なオペランドを生成する責任があります。データパスにはレジスタファイルの実体が含まれており、レジスタファイルの読み書きの調停、およびデータの読み出しと書き込みも担当します。現在、データパスには整数レジスタファイルのキャッシュも設定されており、一部の整数データの読み出しを担当しています。

DataPathモジュールはデータパスの核心部分であり、OG0パイプラインステージ全体とOG1パイプラインステージの前半部分を含みます。OG0パイプラインステージでは、命令間の読み出しポートの調停が行われ、調停に成功した命令のみがレジスタファイルを読み出し、OG1パイプラインステージに進みます。調停に失敗した命令は自身をフラッシュし、前段に発行失敗の応答情報とog0キャンセル信号を発します。OG1パイプラインステージでは、命令はレジスタファイルから返されたデータを受け取り、他の状態情報とともに後続のモジュールに送られます。DataPath内では命令オペランドの最終的な生成は行われず、レジスタファイル、Reg Cache、PcTargetMemから読み出された候補データのみを取得します。最終的なデータは外部のBypassNetworkで生成されます。

### 読み書き調停

発行後にレジスタファイルを読み出す方式を採用しているため、データパスに発行される命令の数はレジスタファイルの読み書きポートの数をはるかに超えます。そのため、調停を行い、リードアービトレーションに成功した命令のみがレジスタを読み出すようにする必要があります。

各レジスタファイルには読み出しアービタがあり、すべての命令の各オペランドのvalidと読み出しアドレスaddrを受け取り、それぞれreadyを返して調停が成功したかどうかの目印とします。命令のオペランドが対応するデータ型（整数、浮動小数点、ベクトル汎用、v0、vl）であり、かつデータソースがregタイプである場合にのみ、validをハイにして調停要求を発します。あるオペランドがレジスタファイルを読み出す必要がない場合、対応するvalidは0となり、このときreadyは常に1を返してアービタを通過させます。各命令について、そのすべてのオペランドが調停を通過した場合にのみ、リードアービトレーション成功と見なされます。読み出しアービタはまた、レジスタファイルの読み出しポート数と同じ数の読み出し要求のセットを出力します。その内容は、各読み出しポートで最後に調停に成功した読み出しアドレスです。この読み出し要求のセットは、実際のデータ読み出しのためにレジスタファイルに送られます。

各レジスタファイルには書き込みアービタがあり、すべての命令の各オペランドのvalidを受け取り、それぞれreadyを返して調停が成功したかどうかの目印とします。命令のデスティネーションレジスタのデータ型が一致し、かつレジスタに書き込む必要がある場合にのみ、validをハイにして調停要求を発します。リードアービトレーションと同様に、要求を発しない命令は常にready=1を受け取って調停を通過します。

読み書きアービタ内部の調停ロジックは、2次モジュールで具体的に紹介します。

### レジスタファイルの読み出し

各レジスタファイルの読み出しアービタは、レジスタファイルの読み出しポート数と同じ数の読み出し要求のセットを出力します。その内容は、各読み出しポートで最後に調停に成功した読み出しアドレスです。これらのアドレスはOG0ステージでレジスタファイルに送られ、読み出し要求が発行されます。OG1ステージでは、対応するデータがレジスタファイルの読み出しデータチャネルから送出されます。各命令のオペランドは、自身のデータ型と使用する読み出しポート番号に基づいて、レジスタファイルの読み出しデータから自身のデータを選択します。

### Reg Cacheの読み出し

DataPath内にはReg Cacheが設定されており、整数ExeUnitとLoad ExeUnitが最近書き戻したデータをキャッシュできます。Reg Cacheは読み書き調停を必要とせず、そのポート数は読み書きが必要なオペランドの数と1対1で対応します。命令オペランドのデータソースがregcacheタイプの場合、Reg Cacheに読み出し要求を発します。OG0ステージでは、valid信号と命令自身が持つRCアドレス信号をReg Cacheに渡し、OG1ステージで対応するデータチャネルからデータを取得できます。

### PCの読み出し

一部の命令はPCをソースオペランドとして読み出す必要があり、PCはDataPath外部のPcTargetMemに保存されています。OGステージでは、DataPathはまずPCを必要とする命令を選別し、そのftq情報をio.fromPcTargetMemインターフェースを介して外部に読み出し要求を発します。OG1ステージでは、外部はこのインターフェースを介して読み出したPC情報を返します。

### レジスタファイルの書き込み

実行ユニットの書き戻し結果は、外部モジュールWbDataPathによって集約され、書き込み要求の形式にパッケージ化されてDataPathに送られます。DataPathは、io.fromIntWb、io.fromFpWb、io.fromVfWb、io.fromV0Wb、io.fromVlWbの5つのインターフェースから返される書き戻し情報を受け取ります。それぞれが対応するレジスタファイルに対応しています。各インターフェースのチャネル数はレジスタファイルの書き込みポート数であり、内容は書き込みイネーブル、書き込みアドレス、書き込みデータです。タイミングの都合上、これらの信号はDataPath内部で1サイクル遅延され、その後直接レジスタファイルの書き込みポートに送られます。

### Reg Cacheの書き込み

Reg Cacheの書き戻しデータは実行ユニットからではなく、バイパスネットワーク内の実行ユニットが書き戻してから2サイクル後のデータから来ます。Reg Cacheは整数ExeUnitとLoad ExeUnitのデータのみを受け入れ、これらのデータはio.fromBypassNetworkインターフェースを介して入力され、その後直接Reg Cacheに送られます。

### og0 cancelの処理

OG0ステージでは、命令はさまざまな理由でキャンセルされることがあり、そのうち自身の理由によるキャンセルはog0 cancelと呼ばれます。命令がog0 cancelと判定されるには2つのケースがあります。1つは自身の読み出しまたは書き込みレジスタファイルの調停失敗、もう1つはog0 cancelの伝播です。DataPathには前回のog0 cancelの情報が保存されており、これは発行幅と同じ長さのベクトルで、各ビットが対応する命令がキャンセルされたかどうかを表します。ある命令が0実行遅延の命令で、かつキャンセルが発生した場合、ベクトルの対応する位置に1が書き込まれます。次のサイクルの命令は、自身のオペランドのウェイクアップソースベクトルとキャンセル情報のベクトルを比較し、ソース命令が前のサイクルでキャンセルされたことを見つけた場合、自身もキャンセルされるべきであることを意味します。

og0 cancelが発生した命令は自身をフラッシュし、OG1ステージには入りません。og0 cancelの発生に加えて、リダイレクトフラッシュやload cancelが発生した命令も自身をフラッシュし、OG1ステージには加わりません。ただし、og0 cancelが発生した命令のみが外部にog0 cancel信号を発します。この信号は、前述のDataPath内部に保存されているog0 cancel情報と同じで、io.og0Cancelインターフェースを介して外部に伝達され、命令のコンシューマ命令をキャンセルするために使用されます。

### 発行キューへの応答

DataPathは発行キューに応答情報を送り、命令が実行ユニットに無事発行されたかどうかを伝えます。OGステージで、命令がog0 cancelした場合、命令の発行は失敗し、発行キューにblock状態を応答して、命令を再発行する必要があることを伝えます。OG0ステージを無事通過した場合、応答情報は送信されません。OG1ステージでは、命令は自身の理由でキャンセルされることはなく、後段が命令を受け入れられるかどうかを見るだけです。受け入れられない場合、命令は実行ユニットに入れず、発行キューにblock状態を応答する必要があります。受け入れられる場合、スカラー計算命令については、命令は必ず成功裏に実行されるため、この時点で発行キューにsuccess状態を応答し、対応するキューエントリをクリアできることを伝えます。ベクトル計算命令については、実行ユニットに入る前にもう1つOG2ステージがあるため、この時点では必ず実行できるとは限らず、発行キューにuncertain状態を応答して、発行キューをそのまま保持させます。メモリアクセス命令については、メモリアクセス実行ユニットに入ってから成功するかどうかが確定するため、キューエントリのクリアの応答はメモリアクセス部分から発せられ、ここでは発行キューにuncertain状態を応答するだけです。


## モジュール設計

### 2次モジュール RFWBCollideChecker

#### 機能

各レジスタファイルには書き込みポートアービタがあり、書き込みポートの調停を担当します。書き込みポートアービタは、このレジスタファイルに書き込むことができるすべての命令の要求（valid信号）を収集し、それぞれについて調停が成功したかどうかのフラグ（ready信号）を返します。

アービタ内部では、ポート番号によって複数のポートアービタに分かれています。各ポートアービタは、そのポートに書き込む命令の要求を収集します。例えば、命令がi番ポートを使用してこのファイルに書き戻す場合、その要求はi番目のポートアービタに送られます。

ポートアービタでは、フォールバック付きの優先度調停方式を採用しています。機能ユニットを設定する際、各ユニットはレジスタファイルの書き込みポートを設定するときに、ポート番号に加えて優先度も設定します。ある時点で複数の命令が同時に書き込み要求を発行した場合、ポートアービタは優先度の高い命令を調停成功とします。

ポートアービタは、要求を発行しなかった命令についてはready=1を保証し、調停成功と見なします。複数の命令が同時に要求を発行した場合、要求を発行した命令のうち1つだけがready=1となり、調停成功となります。

ポートアービタにはフォールバック機能が設定されており、各命令にカウンタを割り当てています。命令が要求を発行して調停に失敗するたびにカウンタが1加算され、命令が要求を発行して調停に成功するとカウンタがクリアされます。カウンタが最大値7に達すると、フォールバック状態がトリガーされます。フォールバック状態では、フォールバックでないすべての命令要求がマスクされ、その後優先度調停が行われます。フォールバックが成功し、命令が調停に成功すると、カウンタがクリアされ、フォールバック状態が解除されます。

### 2次モジュール RFReadArbiter

#### 機能

各レジスタファイルには読み出しポートアービタがあり、読み出しポートの調停を担当します。書き込みポートアービタと同様に、読み出しポートアービタもこのレジスタファイルを読み出すことができるすべてのオペランドの要求を収集し、調停が成功したかどうかのフラグを返します。異なる点は、読み出しポートアービタが収集する要求には読み出しアドレスも含まれており、最終的に各読み出しポートで最終的に調停に成功したアドレスを出力します。これらのアドレスは後でレジスタファイルに送られて読み出し操作が行われます。

アービタ内部では、同様にポート番号によって複数のポートアービタに分かれてそれぞれ調停します。ライトアービトレーションと同様に、各ポートアービタもフォールバック付きの優先度調停方式を採用しています。各ポートが最後に出力するアドレスは、要求を発行して調停に成功したオペランドが提供したアドレスです。ある時点で読み出し要求がない場合、最終アドレスは優先度が最も低いオペランドのアドレスになります。

#### 全体ブロック図

読み出しポートアービタの構造は書き込みポートアービタとほぼ同じであるため、ここでは説明を省略します。主な違いは、各読み出し要求が読み出しアドレスを伴うこと、同時に内部の各ポートアービタが最終アドレスを出力することです。

### 2次モジュール RegFile

#### 機能

DataPathには5つの物理レジスタファイルが設定されています。そのうち整数と浮動小数点はそれぞれ1つのファイルですが、ベクトルはポート数と面積のオーバーヘッドを削減するために3つのファイルに分割されています。VfRegFileは汎用ベクトルレジスタファイルで、ベクトル#1～#31の論理レジスタといくつかの一時レジスタの値を保存します。V0RegFileはv0レジスタファイルで、ベクトル#0の論理レジスタの値のみを保存します。VlRegFileはvlレジスタファイルで、ベクトルvl CSRレジスタの値のみを保存します。

レジスタファイルはバンク設計を使用しており、具体的な状況に応じてS=1、2、4のバンクに分割されます。バンク分割は垂直方向であり、つまり容量N、要素サイズMビットのレジスタファイルは、S個のN * (M / S)サイズのレジスタファイルに分割されます。各要素は各バンクに分割され、レジスタファイルの読み書き時には、すべてのバンクファイルが同時に読み書きされます。

レジスタファイルにはR個の読み出しポートがあり、各読み出しポートにはアドレスraddrとデータrdataの2つの信号がありますが、読み出しイネーブルはありません。ある時点で読み出しアドレスを提供すると、レジスタファイルはこのアドレスを1サイクル遅延させ、次のサイクルでアドレスを使用して対応するデータを読み出し、データインターフェースに送信します。

レジスタファイルにはW個の書き込みポートがあり、各書き込みポートには書き込みイネーブルwen、書き込みアドレスwaddr、書き込みデータwdataの3つの信号があります。ある時点でwenがハイになると、対応するアドレスに指定されたデータが書き込まれ、書き込まれたデータは次のサイクルで見ることができます。整数レジスタファイルには特別な場所があり、0番アドレスには実際にはデータが書き込まれず、常に0の値が保持されます。

### 2次モジュール RegCache

#### 全体ブロック図

![RegCache全体ブロック図](./figure/regcache.png)

#### 機能

Reg CacheはReg Fileのサブセットとして、一部のEXUの最近の書き戻し結果を保存し、元々DataSourceがregタイプであった読み出しデータ要求の一部を担い、Reg Fileの読み出しポート数を削減します。

現在、整数レジスタファイルに対してのみReg Cacheが設定されており、4つのALUがあるEXUと3つのLDUの書き戻し結果のみを保存します。

##### データ部分（RC Data Module）

データ部分のパイプライン位置はReg Fileと同じで、どちらもOG0段階で読み出し要求を発行し、OG1段階でデータを取得します。

データ部分は2つの部分に分かれており、RC_INTは4つのALUがあるEXUの結果を格納し、RC_LSは3つのLDUの結果を格納します。

各部分の内部は全結合構造を採用しており、Reg Cache全体のアドレッシングは統一アドレッシングを使用し、5ビットを使用します。最上位ビットが0の場合はRC_INTを、1の場合はRC_LSを表します。

Reg Cacheの具体的なパラメータ設定は以下の表の通りです。

Table: Reg Cacheの仕様

| Reg Cache | 容量 | ビット幅 | 読み出しポート数 | 書き込みポート数 |
| --- | --- | --- | --- | --- |
| RC_INT | 16 | 64-bit | 23 | 4 |
| RC_LS | 12 | 64-bit | 23 | 3 |

(1) RC dataの読み出し

命令がRCデータを読み出すのは、レジスタファイルの読み出しと似ています。データパスのOG0段階で、データソースがRCタイプのオペランドがRCにデータ読み出し要求を発行し、対応するRCアドレスを送信します。

データパスのOG1段階で、RCデータの結果が得られます。この結果はBypassNetworkに転送され、データソースのタイプに基づいて最終的なデータが多重選択されます。

RCの読み出し時には調停は設定されず、整数レジスタファイルを読み出すことができる各オペランドには専用の読み出しポートが設けられています。

(2) RC dataの書き込み

RC dataはBypassNetworkのbypass段階のデータを使用して書き込まれます。書き込み時のアドレスは、ウェイクアップ信号を発行したときに付随するRCアドレスを使用します。

ウェイクアップを発行してから書き戻しデータがbypass段階に到達するまでに3サイクルの間隔があるため、RC内で選択された置換項目のアドレスを3サイクル遅延させてからデータを書き込む必要があります。

##### 年齢部分（RC Age Timer）

年齢部分は年齢カウンタと年齢行列の2つのモジュールに分かれています。年齢カウンタモジュールは、RCの各項目に2ビットの年齢カウンタを設け、RC項目の読み書き状況に応じて更新します。

同時に、RC_INTとRC_LSそれぞれに対して年齢行列を維持し、周期ごとにそれぞれ4つ、3つの置換対象項目を選択し、それらのRC_Idxを4つのALUのWakeUpQueueと3つのLDUのWakeUpQueueに渡します。各WakeUpQueueは、高速ウェイクアップを発行する際に、対応するRC_Idxを付随させ、そのコンシューマにどの位置からデータを取得すべきかを知らせます。

N項のRCに対して、その年齢行列はN x Nの正方行列であり、各項Age[i][j]はi項とj項の相対的な年齢順序を表し、1であればi項がj項より古く、i項が先に置換されるべきであることを示します。

明らかにAge[i][j] = ~Age[j][i]（i != jの場合）であり、同時にi == jの場合はAge[i][j] = 1と規定します。これにより、実際に保存する必要がある部分は行列の上三角部分であり、N * (N - 1) / 2ビットになります。

(1) 置換アルゴリズム

年齢行列は以下の方法で維持されます：

 - T0時点で各項の状態に基づき、年齢比較関数によってペア間の年齢順序を求め、年齢行列に書き込む
 - T1時点で各行の1の数に基づき、しきい値を超えた項を置換対象として選択する

M項を置換対象として選択する場合、1の数が >= N - M + 1の項が選択されます。1の数がN - M + 1からNまでの項の位置を選択することで、RC_Idxが得られます。

(2) 年齢更新

RCの各項はAgeTimerを維持し、更新規則は以下の通りです：

 - その項が更新されたとき、カウンタをゼロにする
 - 現在読み出し要求がある場合、変更しない（読み出し要求を発行したが命令がキャンセルされた場合も含む）
 - カウンタが最大値に達した場合、変更しない
 - その他の場合、カウンタ+1

```c
if (wen):
    AgeTimerNext = 0
else if (hasReadReq):
    AgeTimerNext = AgeTimer
else if (AgeTimer == 3):
    AgeTimerNext = 3
else:
    AgeTimerNext = AgeTimer + 1
```

(3) 年齢比較

年齢比較関数はAgeTimerNextに基づいて比較し、カウンタが大きいほど古いと見なします。2つの項のカウンタ値が同じ場合、インデックスが小さいほど古いと見なします。

```c
for(i = 0; i < N ; i++)
    for(j = 0; j < N; j++)
        if (i == j)
            AgeNext[i][j] = 1
        else if (i < j)
            if (AgeTimerNext[i] >= AgeTimerNext[j])
                AgeNext[i][j] = 1
            else
                AgeNext[i][j] = 0
        else
            AgeNext[i][j] = ~AgeNext[j][i]
```
