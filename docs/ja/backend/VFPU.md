## 設計仕様

1. ベクトル浮動小数点Mul計算をサポート
2. ベクトル浮動小数点FMA計算をサポート
3. ベクトル浮動小数点Div計算をサポート
4. ベクトル浮動小数点Sqrt計算をサポート
5. fp32, fp64, fp16計算をサポート
6. RV-V1.0バージョンのベクトル浮動小数点命令の計算をサポート

## 機能

VFPUモジュールは、発行キューから発行されたuop情報を受け取り、fuTypeやfuOpTypeなどの情報に基づいてベクトル浮動小数点命令の計算を実行します。主にVFAlu、VFMA、VFDivSqrt、VFCvtの4つのモジュールで構成されます。

VFAluは、主にfadd関連の命令や、比較命令、符号注入命令などの他の単純な命令を担当します。特筆すべきは、リダクションサム命令もuopを分割することでこのモジュールで計算される点です。

VFMAは、主に乗算および積和演算関連の命令を担当します。

VFDivSqrtは、主に除算および平方根関連の命令を担当します。

VFCvtは、主にフォーマット変換および逆数推定関連の命令を担当します。

## アルゴリズム設計

ベクトル浮動小数点演算ユニットの難点は、複数の単一精度フォーマット（オペランドと結果の浮動小数点フォーマットが同じ）の計算と、混合精度（オペランドと結果の浮動小数点フォーマットが異なる）の計算をサポートすることにあります。一般的な半精度（$f16$）、単精度（$f32$）、倍精度（$f64$）を例に、スカラー浮動小数点演算ユニットとベクトル浮動小数点演算ユニットの違いを比較します。

典型的な浮動小数点加算を例にとると、スカラー浮動小数点演算ユニットの場合、3つの単一精度フォーマットの計算をサポートするだけで済みます。このユニットの入力オペランドと出力結果はすべて$64$ビットであるべきで、つまり3つのフォーマットの計算をサポートする必要があります。

(1) $1$個の$f64 = f64 + f64$
(2) $1$個の$f32 = f32 + f32$
(3) $1$個の$f16 = f16 + f16$

一見、これら3つのフォーマットの計算を完了するには3つのモジュールが必要に見えます。しかし、浮動小数点数はすべて符号ビット、指数部、仮数部から構成されており、高精度の浮動小数点数の指数部と仮数部のビット幅は低精度のものよりも大きいため、高精度浮動小数点数のハードウェア設計は低精度浮動小数点数のハードウェア要件を完全に満たすことができます。少し処理を加えることで、ハードウェアに$Mux$（マルチプレクサ）を追加して複数の単一精度フォーマットの計算を互換的にサポートでき、面積はわずかに増加するだけです。

一方、ベクトル浮動小数点演算ユニットはベクトル操作をサポートする必要があり、ベクトル操作の特徴はデータ帯域幅の利用率が高いことです。例えば、スカラー演算ユニットのインターフェースは$64$ビットですが、$f32/f16$を計算する際、有効データは$32/16$ビットしかなく、帯域幅利用率は$50\%/25\%$に急減します。ベクトル演算ユニットのインターフェースも$64$ビットですが、単一精度フォーマット$f32/f16$を計算する際、同時に$2/4$組の操作を実行でき、帯域幅利用率は依然として$100\%$に達します。サポートされる単一精度フォーマットの計算は以下の通りです。

(1) $1$個の$f64 = f64 + f64$
(2) $2$個の$f32 = f32 + f32$
(3) $4$個の$f16 = f16 + f16$

同時に複数の同じフォーマットの浮動小数点数を加算する必要があるため、ハードウェア設計はスカラーよりも困難になりますが、高精度フォーマットのハードウェアを低精度フォーマットの計算に再利用することも可能です。さらに、ベクトル浮動小数点演算ユニットがサポートしなければならないもう一つの特性は混合精度計算です。$RISC-V$ベクトル命令セット拡張は、混合精度計算を必要とする一連の$widening$命令を定義しており、浮動小数点加算ユニットが以下の4つの計算フォーマットもサポートすることを要求しています。

(1) $1$個の$f64 = f64 + f32$
(2) $1$個の$f64 = f32 + f32$
(3) $2$個の$f32 = f32 + f16$
(4) $2$個の$f32 = f16 + f16$

混合精度計算の設計難易度は、複数の単一精度フォーマットよりもはるかに高いです。一方では、異なるデータフォーマットのオペランドはフォーマット変換が必要で、結果と同じフォーマットに変換してから計算するため、ロジックの複雑さが増します。他方では、フォーマット変換は回路のタイミングに非常に大きなプレッシャーをかけます。特に、低精度の非正規化数を高精度の浮動小数点数に変換する場合です。そのため、本稿ではタイミング問題を解決するために、高速なデータフォーマット変換アルゴリズムを特別に設計しました。

以上をまとめると、ベクトル浮動小数点演算器の設計上の難点は、複数の単一精度フォーマットの実装と混合精度フォーマットの実装にあります。本節では、ベクトル浮動小数点加算アルゴリズム、浮動小数点順次累加アルゴリズム、ベクトル浮動小数点融合積和アルゴリズム、ベクトル浮動小数点除算アルゴリズムを順に紹介し、ベクトル浮動小数点演算器の設計上の難点を解決し、周波数$3GHz$に達する高性能なベクトル浮動小数点演算器を実現します。

### ベクトル浮動小数点加算

浮動小数点加算は、科学計算で最もよく使われる算術演算の一つです。概念は単純ですが、従来のシングルパス浮動小数点加算アルゴリズムは2〜3回の符号付き加算ステップを必要とし、これは比較的時間のかかる操作です。デュアルパス浮動小数点加算アルゴリズムは、最悪の場合でもクリティカルパス上に1回の符号付き加算操作しかないため、シングルパスアルゴリズムに比べて速度面で大きな利点があります。本稿では、デュアルパス浮動小数点加算アルゴリズムを基に、より高速な改良版デュアルパス浮動小数点加算アルゴリズムを設計しました。本節ではまず、単一精度フォーマットのシングルパス浮動小数点加算アルゴリズム、デュアルパス浮動小数点加算アルゴリズム、改良版デュアルパス浮動小数点加算アルゴリズムを紹介し、最後にベクトル浮動小数点加算アルゴリズムを紹介します。

浮動小数点加算の式は、$fp\_result = fp\_a + fp\_b$と表されます。$fp\_a$と$fp\_b$の符号が同じ場合、有効数字をアラインメントした後に加算が行われます。この状況を等価加算と呼びます。$fp\_a$と$fp\_b$の符号が異なる場合、有効数字をアラインメントした後に減算が行われます。この状況を等価減算と呼びます。非正規化数の指数が$0$の場合と、正規化数の指数が$1$の場合に対応する正規化された指数は同じであるため、指数差を計算する際には、指数が$0$の場合は1として扱うべきです（これを正規化指数と呼びます）。正規化指数の差の絶対値が、正規化された指数の差となります。

#### シングルパス浮動小数点加算アルゴリズム

従来のシングルパス浮動小数点加算演算は、図に示すように以下のステップで構成されます。

![シングルパス浮動小数点加算アルゴリズム](./figure/SinglePassFloating-pointAddition.svg)

(1) 正規化指数減算（Exponent subtraction, $ES$）：正規化指数の差$d = |Ea - Eb|$を求めます。$Ea$、$Eb$はともに正規化指数です。

(2) アラインメント（Alignment, $Align$）：小さい方のオペランドの有効数字を$d$ビット右にシフトします。大きい方の指数を$Ef$と記録します。

(3) 有効数字加算（Significand addition, $SA$）：有効操作$Eo$に基づいて加算または減算を実行します。$Eo$は浮動小数点加算ユニットの加算器が実際に実行する算術演算で、2つの浮動小数点オペランドの符号ビットによって決まります。

(4) 変換（Conversion, $Conv$）：有効数字加算の結果が負の場合、結果を符号-絶対値表現に変換します。変換は1回の加算ステップで完了し、変換結果は$Sf$で表されます。

(5) 先行ゼロ検出（Leading zero detection, $LZD$）：必要な左シフトまたは右シフト量を計算し、それを$En$で表します。右シフトは正、それ以外は負です。

(6) 正規化（Normalization, $Norm$）：$En$ビットシフトして有効数字を正規化し、$En$を$Ef$に加算します。

(7) 丸め（Rounding, $Round$）：$IEEE-754$標準に従って丸めを行い、必要に応じて$Sf$の$LSB$に$1$を加算します。このステップはオーバーフローを引き起こす可能性があり、その場合は仮数結果を1ビット右にシフトし、同時に指数$Ef$に$1$を加算する必要があります。
