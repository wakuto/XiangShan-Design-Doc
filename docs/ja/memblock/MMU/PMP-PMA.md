# 2次モジュール PMP&PMA

PMPには以下のモジュールが含まれ、PMAチェックはPMPモジュール内に組み込まれています。

1. PMP (分散PMPおよびPMAレジスタ)
    1. PMP pmp (フロントエンド)
    2. PMP pmp (メムブロック)
    3. PMP pmp (L2TLB)
2. PMPChecker (PMPおよびPMAチェッカー、同サイクルで結果を返す)
    1. PMPChecker PMPChecker (フロントエンド)
    2. PMPChecker PMPChecker_1 (フロントエンド)
    3. PMPChecker PMPChecker_2 (フロントエンド)
    4. PMPChecker PMPChecker_3 (フロントエンド)
    5. PMPChecker PMPChecker (L2TLB)
    6. PMPChecker PMPChecker_1 (L2TLB)
3. PMPChecker_8 (PMPおよびPMAチェッカー、次のサイクルで結果を返す)
    1. PMPChecker_8 PMPChecker (メムブロック)
    2. PMPChecker_8 PMPChecker_1 (メムブロック)
    3. PMPChecker_8 PMPChecker_2 (メムブロック)
    4. PMPChecker_8 PMPChecker_3 (メムブロック)
    5. PMPChecker_8 PMPChecker_4 (メムブロック)
    6. PMPChecker_8 PMPChecker_5 (メムブロック)

## 設計仕様

1. 物理アドレス保護をサポート
2. 物理アドレス属性をサポート
3. PMPとPMAの並列実行チェックをサポート
4. 動的および静的チェックをサポート
5. 分散PMPおよび分散PMAをサポート
6. 例外処理メカニズムをサポート

## 機能

### 物理アドレス保護のサポート

香山プロセッサは物理アドレス保護（PMP）チェックをサポートしており、PMPはデフォルトで16エントリで、パラメトリックに変更できます。タイミングを考慮して、分散複製実装方法が採用されています。CSRユニットのPMPレジスタはCSRRWなどの命令を担当します。PMPレジスタのコピーは、フロントエンドの命令フェッチ、バックエンドのメモリアクセス、およびページテーブルウォーカーの場所に維持され、CSRユニットのPMPレジスタと一致するようにCSR書き込み信号をプルすることで一貫性が確保されます。

PMPレジスタのフォーマット、リセット値などについては、香山オープンソースプロセッサユーザーマニュアルおよびRISC-V特権レベルマニュアルを参照してください。

### 物理アドレス属性のサポート

物理メモリ属性（PMA）の実装は、PMPのようなアプローチを採用しており、PMP構成レジスタの2つの予約ビットを利用し、それぞれアトミック操作とキャッシュ可能性のサポートを示すアトミックおよびキャッシュ可能として設定されています。PMPレジスタには初期値がありませんが、PMAレジスタはデフォルトで初期値があり、プラットフォームのアドレス属性と一致するように手動で設定する必要があります。PMAレジスタは、Mモードで予約済みのCSRアドレスを利用し、デフォルトで16エントリで、パラメトリックな変更が可能です。

デフォルトのPMA構成については、香山オープンソースプロセッサユーザーマニュアルを参照してください。

### PMPとPMAの並列チェック実行

PMPとPMAのチェックは並列に実行されます。いずれかの権限に違反した場合、操作は不正となります。コア内のすべての物理アドレスアクセスには、ITLBおよびDTLBチェック後、およびページテーブルウォーカー、ハイパーバイザページテーブルウォーカー、および最終レベルページテーブルウォーカーのメモリアクセス前に、物理アドレス権限チェックが必要です。ITLB、DTLB、ページテーブルウォーカー、最終レベルページテーブルウォーカー、およびハイパーバイザページテーブルウォーカーで使用される分散PMP、PMA、および対応するPMPおよびPMAチェッカーを[@tbl:PMP-PMA-modules]に示します。つまり、フロントエンド、メムブロック、およびL2 TLBはそれぞれPMPおよびPMAレジスタのコピーを維持し（セクション5.2.5参照）、それぞれのPMPおよびPMAチェッカーを駆動します。

### 動的チェックと静的チェック

マニュアルの規定によれば、PMPとPMAのチェックは動的チェックであるべきです。つまり、TLB変換後、変換後の物理アドレスを使用して物理アドレス権限チェックを行う必要があります。フロントエンド、L2 TLB、およびメムブロックの5つのPMPChecker（[@tbl:PMP-PMA-modules]参照）はすべて動的チェックです。タイミングを考慮して、DTLBのPMPおよびPMAチェック結果は事前にクエリし、リフィル時にTLBエントリに格納できます。これが静的チェックです。具体的には、L2 TLBのページテーブルエントリがDTLBにリフィルされるとき、同時にリフィルされたページテーブルエントリがPMPおよびPMAに権限チェックのために送信され、チェックで得られた属性ビット（R、W、X、C、アトミックを含む。これらの属性ビットの具体的な意味についてはセクション5.4参照）が同時にDTLBに格納されます。これにより、これらのチェック結果を再度チェックすることなくメムブロックに直接返すことができます。静的チェックを実現するには、PMPとPMAの粒度を4KBに上げる必要があります。

現在、PMPおよびPMAチェックは昆明湖のタイミングボトルネックではないため、静的チェックは採用されておらず、すべて動的チェック方式が使用されています。つまり、TLBクエリで物理アドレスを取得した後、チェックが行われます。昆明湖V1のコードには静的チェックは含まれておらず、動的チェックのみが含まれていることに再度注意してください。ただし、互換性のために、PMPとPMAの粒度は依然として4KBに維持されています。

動的チェックと静的チェックで得られる結果情報は次のとおりです。

* 動的チェック：instアクセスフォールト、loadアクセスフォールト、storeアクセスフォールトが発生したかどうかを返します。チェックされた物理アドレスがmmioアドレス空間に属しているかどうか。
* 静的チェック：チェックされた物理アドレスの属性ビット（R、W、X、C、アトミックを含む）を返します。昆明湖V1はデフォルトでは静的チェックを採用しないことに注意してください。

### 分散PMPおよびPMA

PMPとPMAの具体的な実装には、CSRユニット、フロントエンド、メムブロック、L2 TLBの4つの部分が含まれます。CSRユニットは、これらのPMPおよびPMAレジスタの読み書きに対するCSRRWなどのCSR命令に応答する責任があります。CSRユニットはITLB、DTLB、L2 TLBから遠く離れているため、物理アドレスチェックと物理属性チェックのためにITLB、DTLB、L2 TLBにPMPとPMAのバックアップを保存する必要があります。このため、分散PMPとPMAを実装し、ITLB、DTLB、L2 TLBの近くにこれらのレジスタのバックアップを保存する必要があります。

フロントエンド、メムブロック、およびL2 TLBには、アドレスチェックを担当するこれらのPMPおよびPMAレジスタのバックアップが含まれており、CSRの書き込み信号をプルすることで、これらのレジスタの内容の一貫性を保証できます。L1 TLBの面積は比較的小さいため、PMPおよびPMAレジスタのバックアップはフロントエンドまたはメムブロックに保存され、それぞれITLBおよびDTLBにチェックを提供します。L2 TLBの面積は比較的大きいため、PMPおよびPMAレジスタのバックアップはL2 TLBに直接保存されます。

### PMPおよびPMAのチェックフロー

ITLB、DTLBで物理アドレスが取得された後、およびL2 TLBのページテーブルウォーカー、最終レベルページテーブルウォーカー、およびハイパーバイザページテーブルウォーカーがメモリにアクセスする前に、物理アドレスチェックを行う必要があります。ITLB、DTLB、L2 TLBは、PMPおよびPMA構成レジスタ、アドレスレジスタに関する情報をPMPCheckerに提供する必要があります。PMPおよびPMAアドレスレジスタは、下位から上位に向かって連続する1の数を数えます（PMPおよびPMAの粒度は4KBであるため、最小は12です）。クエリする物理アドレス。実行（ITLB）、読み書き（L2 TLB、LoadUnits、StoreUnits）、アトミック読み書き（AtomicsUnit）など、クエリする権限の種類。
