# 3次モジュール ハイパーバイザページテーブルウォーカー

ハイパーバイザページテーブルウォーカーは、以下のモジュールを指します。

* HPTW hptw

## 設計仕様

1. Gステージの3レベルページテーブルへのアクセスをサポート
2. メモリへの要求送信をサポート
3. ページキャッシュへのリフィル信号の送信をサポート
4. 例外処理をサポート
5. バイパスの特別処理

## 機能

### Gステージの3レベルページテーブルへのアクセスをサポート

HPTWの全体的な設計は、基本的にPTWと同じで、一度に1つの要求しか処理できません。HPTWは、3レベルページテーブルの完全な第2段階変換を実行できます。変換中にメモリアクセスが必要な場合、メモリアクセスアドレスに対してPMPチェックを実行します。エラーが検出された場合は即座にリターンし、それ以外の場合はメモリアクセス要求を送信します。HPTWがリターンするシナリオは次のとおりです。

1. リーフノードへのアクセス
2. アクセス中にページフォールトまたはアクセスフォールトが発生

### メモリへの要求送信をサポート

PTWおよびLLPTWと同様に、HPTWはページテーブルにアクセスする際にメモリに要求を送信する必要があり、これはアービタを介して送信されます。

### ページキャッシュにリフィル信号を送信する

PTWから結果を受信した後、HPTWはページキャッシュにリフィル要求を送信し、返されたページテーブルエントリを埋めます。HPTWは、ページキャッシュを埋めるために必要な情報を提供します。

### 例外処理メカニズム

ページフォールトまたはアクセスフォールト例外が発生した場合、HPTWは直接PTWまたはLLPTWにリターンします。

### バイパスの特別処理

バイパス要求の場合、通常は再クエリのためにミスキューに配置されます。ただし、hptw要求（つまり、isHptwReqが有効な場合）は、ブロッキングを回避するためにミスキューには配置されません。したがって、バイパス要求が発生した場合、ページキャッシュに重複したページテーブルエントリが埋め込まれるのを防ぐために、hptw要求がHPTWに渡されるときにバイパス信号が有効である場合、メモリから返された結果はページキャッシュをリフィルしません。

## 全体ブロック図

HPTWの状態遷移図を[@fig:HPTW-states]に示します。

![ハイパーバイザページテーブルウォーカーステートマシン遷移図](../figure/image43.jpeg){#fig:HPTW-states}

ステートマシンの各状態の説明は次のとおりです。

* idle：ハイパーバイザページテーブルウォーカーステートマシンの初期状態。PTW要求を受信すると、pmp_check状態に遷移します。
* pmp_check：この状態では、アクセスする物理アドレスがPMPおよびPMAチェックのためにPMPモジュールに送信され、次のサイクルでmem_req状態に遷移します。PMPモジュールは、同じサイクル内にアクセスフォールトの物理アドレスチェック結果を返す必要があります。
* mem_req：PMPおよびPMAチェックの結果に基づいて、アクセスフォールトが検出された場合はcheck_pte状態に遷移し、それ以外の場合はメモリに要求を送信します。mem_req状態では、メモリとのハンドシェイクが成功するまで待機し続け、要求が送信されたことを示し、その後mem_resp状態に遷移します。
* mem_resp：mem_req状態では、ハイパーバイザページテーブルウォーカーはメモリにPTW要求を送信しました。mem_resp状態では、ハイパーバイザページテーブルウォーカーはメモリからの応答を待ちます。メモリ応答を受信し、メモリと正常にハンドシェイクすると、check_pte状態に遷移します。
* check_pte：この状態は、次の操作を決定するために現在のクエリ状況を評価します。この状態で処理されるシナリオは次のとおりです。
    1. アクセスフォールトまたはページフォールトの場合、PTWまたはLLPTWに返されます。
    2. メモリから返されたページテーブルがリーフノードの場合、直接PTWまたはLLPTWに返されます。
    3. リーフノードでない場合、物理アドレスはPMP＆PMAチェックのためにPMPモジュールに送信され、状態はmem_reqに遷移し、上記のプロセスを繰り返します。
