# 3次モジュール 最終レベルページテーブルウォーカー

最終レベルページテーブルウォーカーは、以下のモジュールを指します。

* LLPTW llptw

## 設計仕様

1.  最終レベルのページテーブルへのアクセスをサポートします。
2.  複数の要求の並列処理をサポートします。
3.  メモリへのPTW要求の送信をサポートします。
4.  ページキャッシュへのリフィル信号の送信をサポートします。
5.  例外処理メカニズムをサポートします。
6.  第2段階の変換をサポートします。

## 機能

### 最終レベルのページテーブルにアクセスする

最終レベルページテーブルウォーカーは、最終レベルのページテーブルにアクセスする役割を担い、同時にページテーブルウォーカーのアクセスの並列性を高めます。ページテーブルウォーカーは一度に1つの要求しか処理できませんが、LLPTWは複数の要求を同時に処理できます。重複する要求が存在する場合、LLPTWはそれらをマージせず、これらの要求を記録してメモリアクセス結果を共有し、冗長なメモリアクセスを回避します。

LLPTWは、ページキャッシュまたはページテーブルウォーカーのいずれかから要求を受信することがあります。ページキャッシュからの要求の場合、第2レベルのページテーブルにヒットし、第3レベルのページテーブルにミスし、バイパス要求ではないという条件を満たす必要があります。ページテーブルウォーカーからの要求の場合、最終レベルのページテーブルのみが欠落しているという条件をすでに満たしているため、LLPTWは直接メモリにアクセスできます。ページキャッシュとページテーブルウォーカーからの要求は、アービタによって調停され、LLPTWに転送されます。

ページテーブルウォーカーとLLPTWは連携して、ページテーブルウォークプロセス全体を完了します。メモリアクセスの並列性を向上させるために、LLPTWは要求に異なるIDを割り当て、複数のインフライト要求が共存できるようにします。異なる要求間で最初の2レベルのページテーブルが同じである可能性があること、および最初の2レベルのミス確率が最終レベルよりも低いことを考慮すると、最初の2レベルの並列性を高める必要はありません。代わりに、ページテーブルウォーカーは単一の要求を処理して、設計の複雑さを軽減します。

### 複数の要求の並列処理

LLPTWは複数の要求を同時に処理でき、並列処理の数はLLPTWのエントリ数に等しくなります。それらの間に重複する要求がある場合、LLPTWはそれらをマージせず、これらの要求を記録し、冗長なメモリアクセスを回避するためにメモリアクセス結果を共有します。LLPTWの各エントリは、ステートマシンを介してメモリアクセスの状態を維持します。LLPTWが新しい要求を受信すると、新しい要求のアドレスを既存の要求のアドレスと比較します。アドレスが一致する場合、既存の要求の状態が新しい要求にコピーされます。したがって、同じアドレスを持つ要求はメモリアクセス結果を共有でき、冗長なアクセス要求を回避できます。

### メモリへのPTW要求の送信

ページテーブルウォーカーの動作と同様に、LLPTWもメモリにPTW要求を送信できます。LLPTWは重複する要求をマージし、メモリアクセス結果を共有して、冗長なメモリアクセスを回避します。メモリから返されるデータは比較的多きい（512ビット）ため、返された結果はLLPTWに保存されません。以前に送信されたPTW要求に対するメモリ応答を待っている間にPTW要求がLLPTWに送信され、新しい要求の物理アドレスがメモリから返された物理アドレスと一致する場合、新しい要求はミスキューに転送され、ページキャッシュへの次のアクセスを待ちます。

### ページキャッシュにリフィル信号を送信する

最終レベルページテーブルウォーカーがページキャッシュにリフィル信号を送信するロジックは、ページテーブルウォーカーのロジックと似ているため、ここでは詳述しません。

### 例外処理メカニズム

最終レベルページテーブルウォーカーでアクセスフォールト例外が発生する可能性があり、それはL1 TLBに配信されます。L1 TLBは要求元に基づいてそれを処理します。このドキュメントのセクション6「例外処理メカニズム」を参照してください。

### 第2段階の変換をサポートします。

state_hptw_req、state_hptw_resp、state_last_hptw_req、およびstate_last_hptw_respの4つの新しい状態が追加されました。2段階変換要求がLLPTWに入ると、まず第2段階変換を実行して第3レベルページテーブルの実際の物理アドレスを取得します。アドレスチェックとメモリアクセスの後、第3レベルページテーブルが取得されると、最終的な物理アドレスを取得するために返す前にもう1つの第2段階変換が必要です。

各エントリは、各第2段階変換の結果を格納するためにhptw resp構造で拡張されました。最初の第2段階変換時に、hptwが戻ると、すべてのエントリがチェックされます。同じキャッシュラインに対するメモリアクセス要求がすでに発行されている場合、直接mem waitingフェーズに入ります。

LLPTWは、第2段階変換のために追加のアービタを導入します。hyper_arb1は、hptw req状態に対応する最初の第2段階アドレス変換に使用されます。hyper_arb2は、last hptw req状態に対応する2番目の第2段階アドレス変換に使用されます。hptw_req_arbの入力はhyper_arb1とhyper_arb2で構成され、出力はhptw要求信号です。
