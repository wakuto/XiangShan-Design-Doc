# 3次モジュール ページテーブルウォーカー

ページテーブルウォーカーは、以下のモジュールを指します。

* PTW ptw

## 設計仕様

1. ページテーブルの最初の2レベルへのアクセスをサポートします。
2. メモリへのPTW要求の送信をサポートします。
3. LLPTWへのPTW要求の転送をサポートします。
4. ページキャッシュへのリフィル信号の送信をサポートします。
5. 例外処理をサポートします。
6. 2段階のアドレス変換をサポートします。

## 機能

### ページテーブルの最初の2レベルへのアクセス

ページテーブルウォーカーは、基本的には、仮想アドレスを使用してページテーブルをレベルごとに横断し、物理アドレスを取得するステートマシンです。一度に1つの要求しか処理できず、最大でもページテーブルの最初の2レベルにしかアクセスできないため、メモリアクセス能力は限られています。仮想アドレスから物理アドレスへの変換の動作はマニュアルの記述と一致しており、メモリアクセス前に物理アドレスのPMPチェックが必要です。PMPチェックでエラーが発生した場合は即座にリターンし、そうでなければメモリまたはLLPTWにPTW要求を送信します。H拡張の追加により、PTWは依然として第1段階の最初の2レベルの変換を担当しますが、これらの変換中に計算された物理アドレスは、メモリアクセス前に真の物理アドレスを取得するために第2段階の変換を経る必要があります。また、第2段階のみまたは第1段階のみの変換のシナリオもサポートしています。メモリがページテーブルエントリを返す際にもPMPチェックが実行されます。ページテーブルウォーカーは、以下の3つの条件のいずれかが発生するまでこれらの操作を続けます。

1. リーフノード（ラージページ）にアクセスすると、直接L1 TLBに返されます（全ステージ変換の場合、返す前に第2段階変換が実行されます）。
2. 第2レベルのページテーブルにアクセスすると、LLPTWに返され、LLPTWが最終レベルのページテーブルアクセスを処理します。
3. アクセス中にページフォールトまたはアクセスフォールトが発生しました。

### メモリまたはllptwにPTW要求を送信します。

ページテーブルウォーカーがページテーブルの最初の2つのレベルにアクセスする場合、メモリにPTW要求を送信する必要があります。最初の2つのレベルへのアクセスが完了すると、LLPTWにPTW要求を送信する必要があります。PTW、LLPTW、およびHPTWからメモリに送信される要求は、ディスパッチ前にアービトレーションが必要であり、TileLinkプロトコルのAおよびDチャネルのソース信号は、要求がPTW、LLPTW、またはHPTWから発信されたかどうかを示します。

### ページキャッシュにリフィル信号を送信する

ページテーブルウォーカーがメモリに送信したPTW要求が応答を受け取ると、ページキャッシュにリフィル要求を送信します。Memは返されたページテーブルエントリをページキャッシュにリフィルしますが、ページテーブルウォーカーは仮想ページ番号、ページテーブルレベル、およびページテーブルタイプをさらに提供する必要があります。変換要求が2段階アドレス変換要求であるかどうかに応じて、ページキャッシュにリフィルされるページテーブルはnoS2xlateとonlyStage1に分類されます。

### 例外処理メカニズム

ページテーブルウォーカーでアクセスフォールト例外が発生する可能性があり、それはL1 TLBに配信されます。L1 TLBは要求元に基づいてそれを処理します。このドキュメントのセクション6「例外処理メカニズム」を参照してください。

## 全体ブロック図

ページテーブルウォーカーの本質は、要求イベントと応答イベントに分かれたソフトウェアステートマシンです。各状態は要求イベントと応答イベントのペアで表され、ここでは明確にするために一般的なステートマシン遷移図と関係を使用して示されています。L2 TLB内のページテーブルウォーカーと他のモジュール間の接続の詳細については、セクション5.3.3を参照してください。

ステートマシンの遷移図を[@fig:PTW-states]に示します。

![ページテーブルウォーカーステートマシンの状態遷移図](../figure/image40.jpeg){#fig:PTW-states}

状態を明確に表現するために、さまざまなタイプの要求を2つのタイプのステートマシンに分割し、それぞれに独自の遷移図を持たせます。

noS2xlateまたはonlyStage1要求のステートマシン（図の左側）の場合、各状態の説明は次のとおりです。

* idle：ページテーブルウォーカーの初期状態。要求を受信すると、PTWはpmpチェック状態に入ります。
* pmpチェック：この状態では、アクセスされる物理アドレスがPMPおよびPMAチェックのためにPMPモジュールに送信されます。次のサイクルで、mem req状態に入ります。PMPモジュールは、アクセスフォールトが発生したかどうかを示すチェック結果を同じサイクルで返します。
* mem req：チェック結果に基づいて、アクセスフォールトが発生した場合、直接最終チェックpte状態に入ります（chiselコードではmem_addr_update信号が有効であることで示されます）。アクセスフォールトが発生しない場合、メモリアクセス要求が送信され、状態はmem respに遷移します。
* mem resp：この状態はメモリからの応答を待ち、受信時にチェックPTE状態に遷移します。
* check pte：この状態では、現在の要求が検査され、次のアクションが決定されます。
	1. リーフノードが見つからずアクセスフォールトも発生しておらず、現在の level が第1段階のページテーブルの場合は mem req 状態に戻ります。
	2. アクセスフォールトが発生した場合は L1 TLB へ直ちに返却し、状態は idle に戻ります。
	3. 第2レベルのページテーブルを見つけたもののリーフノードでない場合は、LLPTW にリクエストを転送します。
	4. リーフノード（ラージページ）を見つけた場合は、結果を L1 TLB に返します。

allStage と onlyStage2 のリクエストについては以下の通りです。

* idle：これらのリクエストを受信すると hptw req 状態に入り、直ちに第2段階の翻訳を開始します。
* hptw req：L2TLB に第2段階翻訳リクエストを送信し、送信完了後は hptw resp 状態へ遷移します。
* hptw resp：第2段階翻訳の応答を待ちます。応答が返ってきたとき、リクエストが onlyStage2 であれば check pte に進み、それ以外（allStage）の場合は pmp check へ進みます。
* pmp check：アクセス対象の物理アドレスを PMP モジュールへ渡して PMP / PMA チェックを実行します。次サイクルで mem req 状態に遷移し、同サイクルでアクセスフォールトの有無が返されます。
* mem req：アクセスフォールトであれば即座に check pte へ遷移します（Chisel コードでは mem_addr_update 信号が有効）。エラーが無ければメモリアクセスを発行し、mem resp に遷移します。
* mem resp：メモリ応答を待ち、受信後に check pte 状態へ遷移します。
* check pte：onlyStage2 以外（allStage）の場合でリーフノードが見つからずアクセスフォールトも無ければ、再び hptw req へ戻ります。リーフノードが見つからず level が第2段階であれば LLPTW に転送します。last s2xlate 信号が有効であれば返却前に第2段階翻訳をもう一度実行します（onlyStage2 では不要）。リーフノードが見つかり最後の翻訳も完了していれば L1 TLB へ返却します。

なお、PTW は stage1 でヒットした allStage リクエストも処理します。この場合は第2段階翻訳を1回行ったのち、即座に L1 TLB に返却します。

## インターフェース一覧

ページテーブルウォーカーの信号は以下のカテゴリに分類できます。

1.  req：PTW が受け付けるのはページキャッシュからのリクエストだけで、所定の条件を満たす必要があります（詳細は 5.3.7 節参照）。
2.  resp：PTW がラージページに到達した場合、または PMP / PMA チェックでエラーが発生した場合に、情報を L1 TLB へ返します。
3.  llptw：最後のレベルのページテーブルに任せる必要がある場合、または PMP / PMA チェックでエラーが発生した場合に、PTW から LLPTW へ情報を転送します。
4.  mem：PTW とメモリ間の req / resp インターフェース。ハンドシェイク信号は PTW 状態機の遷移制御にも利用されます。
5.  pmp：PMP / PMA チェックのために PTW と PMP モジュールがやり取りするインターフェース。
6.  refill：メモリから得たページテーブルエントリと付随情報をページキャッシュへリフィルするためのインターフェース。
7.  hptw：ゲスト物理アドレスを得た後、L2TLB に第2段階翻訳を要求し、結果を受け取るためのインターフェース。

詳細はインターフェース一覧ドキュメントを参照してください。

## インターフェースタイミング

ページテーブルウォーカーは valid-ready 方式で L2 TLB 内の他モジュールと通信します。信号は多岐にわたりますが、特筆すべきタイミング上の留意点はないため、ここでは詳細を割愛します。
