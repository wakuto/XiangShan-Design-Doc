# エラー処理とカスタムフォールトインジェクション命令

## 機能説明

CtrlUnitは、DCacheのECCエラーインジェクションを制御するために使用されます。各コアのL1DCacheには、メモリマップされたレジスタで制御されるコントローラが設定されており、ECCをサポートする各ハードウェアユニットにはコントロールバンクが割り当てられています。CtrlUnit内の設定レジスタは、MMIOロード/ストア命令を介してアクセスされます。レジスタが設定されると、L1 DCacheは最初の読み取り操作（例：ロード命令またはMainPipeアクセス）でECCエラーをトリガーします。

### 特徴1：アドレス空間

* アドレス空間0x38022000-0x3802207F、合計128バイトは、各ハートのローカル空間です。

### 特徴2：DCacheコントロールバンク

* 図\ref{fig:CtrlBank}に示すように、各コントロールバンクには、ECCCTL、ECCEID、ECCMASKのレジスタが含まれており、それぞれ8バイトのサイズです。

![CtrlBankレイアウト](./figure/DCache-ECCCtrlBank.svg){#fig:CtrlBank width=17%}

* ECCCTL (ECC Control): ECCインジェクション制御レジスタ

  ![ECCCTL](./figure/DCache-ECCCTL.svg){#fig:EccCtrl width=50%}

  * ese (error signaling enable): インジェクションが有効であることを示し、0に初期化されます。インジェクションが成功すると、eseはローにプルされます。

  * pst: インジェクションサポート信号。pst=1の場合、ECCEIDカウンタが0にデクリメントされ、インジェクションが成功した後、インジェクションタイマーは以前に設定されたECCEID値にリセットされて再インジェクションされます。pst==0の場合、インジェクションは1回だけ行われます。

  * ede (error delay enable): カウンタがアクティブであることを示し、0に初期化されます。
    * ese==1かつede==0の場合、エラーインジェクションは即座に有効になります。
    * ese==1かつede==1の場合、インジェクションはECCEIDが0にデクリメントされた後にのみ有効になります。

  * cmp (component): インジェクションターゲットを示し、0に初期化されます。
    * 1’b0: インジェクションターゲットはタグ
    * 1’b1: インジェクションターゲットはデータ

  * bank: バンク有効信号、0に初期化されます。バンク内のビットが設定されると、対応するマスクがアクティブになります。

* ECCEID (ECC Error Inject Delay): ECCインジェクション遅延コントローラ。

  ![ECCEID](./figure/DCache-ECCEID.svg){#fig:EccEid width=50%}

  * ese==1かつede==1の場合、0に達するまでデクリメントが開始されます。現在、コアと同じクロック周波数が使用されていますが、分周することも可能です。ECCインジェクションはDCacheアクセスに依存するため、EIDのタイミングとECCエラートリガーのタイミングが一致しない場合があります。

* ECCMASK (ECC Mask): ECCインジェクションマスクレジスタ。

  ![ECCMASK](./figure/DCache-ECCMASK.svg){#fig:EccMask width=50%}

  * 0は反転なし、1は反転を示します。タグインジェクションは、ECCMASK0内のタグ長に対応するビットのみを使用し、超過したビットは効果がありません。

### 特徴3：バスエラーユニットコントローラ

* DCacheのECCエラーは、統一的にバスエラーユニットコントローラに送信されて処理されます。バスエラーユニットコントローラが保存する情報は次のとおりです。

  表: バスエラーユニットが保存する情報

  | フィールド | 説明 | 初期値 | アドレス |
  | --- | --- | --- | --- |
  | cause | エラーイベントの原因 | 0 | 0x38010000 |
  | value | エラーイベントの物理アドレス | 未定義 | 0x38010008 |
  | enable | イベント有効マスク | 1 | 0x38010010 |
  | global_interrupt | グローバル割り込み有効マスク | 0 | 0x38010018 |
  | accrued | 累積イベントマスク | 0 | 0x38010020 |
  | local_interrupt | ハートローカル割り込み有効マスク | 0 | 0x38010028 |

  * アドレス空間
    バスエラーユニットの物理アドレス空間は0x38010000 - 0x38010fffです。

  * サポートされるエラータイプ
    * ICache ECCエラー
    * DCache ECCエラー
    * L2Cache ECCエラー

  * 制御される割り込み
    * ローカル割り込み：バスエラーユニットが存在するハートにのみ報告でき、バックエンドに報告され、バックエンドが割り込み処理を担当します。現在、NMI_31割り込みが使用されています。
    * グローバル割り込み：グローバル割り込みが発生した場合、バスエラーユニットは割り込み情報をPLICに送信し、PLICが割り込みの報告を担当します。

### 特徴4：L1 DCache ECCエラー処理プロセス

* エラー報告
  * タグECCエラー：いずれかのウェイでECCエラーが発生した場合、ECCエラーが発生したと判断されます。

    表: タグECCエラーとタグヒットの関係

    | ヒット | エラー | タグエラー |
    | --- | --- | --- |
    | N | N | N |
    | N | Y | Y (おそらくヒット) |
    | Y | N | N |
    | Y | Y(エラーありでヒット) | Y |
    | Y | Y(エラーなしでヒット) | N |

    表中のタグヒットとタグECCエラーと判断結果の関係

    * データECCエラー：ヒットしたラインでECCエラーが発生した場合、ECCエラーが発生したと見なされます。ヒットしない場合は処理されません。
    * 命令アクセスがECCエラーをトリガーした場合、それはハードウェアエラーと見なされ、例外が報告されます。
    * トリガーされたエラーはすべて、エラー情報をBEUに送信する必要があります。ハードウェアがエラーを検出すると、BEUに報告し、NMI外部割り込みをトリガーします。

* 通常のメモリアクセス命令
  * ロードなどの通常のメモリアクセス命令の場合、実行はタグまたはデータECCエラーのみをトリガーし、これらはハードウェアエラー（19）とともにBEUに報告されます。

* プローブ/スヌープ
  * プローブ/スヌープの場合
    * タグECCエラーが発生した場合、キャッシュ状態を変更する必要はなく、corrupt=1のProbeAckリクエストをL2に返す必要があります。
    * データECCエラーが発生した場合、ルールに従ってキャッシュ状態を変更し、データを返す必要がある場合は、corrupt=1のProbeAckDataリクエストをL2に返す必要があります。

* 置換/追い出し
  * 置換/追い出しの場合、
    * タグECCエラーが発生した場合、corrupt=1のReleaseリクエストをL2に返す必要があります。
    * データECCエラーが発生した場合、corrupt=1のReleaseDataリクエストをL2に返す必要があります。

* DCacheへのストア
  * SbufferからDCacheへのデータ書き込みの場合
    * タグECCエラーが発生した場合、キャッシュラインは置換/追い出しプロセスに従って解放され、データはエラーをL2に報告せずにDCacheに書き込まれます。
    * データECCエラーが発生した場合、データはエラーをL2に報告せずに直接書き込まれます。

* アトミック操作
  * アトミック操作の場合、例外は報告されますが、エラーはL2に転送されません。

* 複数エラーの選択
  * 複数のエラーが同時に発生した場合の優先順位は、ldu0 > ldu1 > ldu2 > MainPipeです。

## インターフェースタイミング

### 設定レジスタのタイミング

* 設定レジスタは、図\ref{fig:DCache-Error-Config-Timing}に示すように、tilelinkインターフェースを介して読み書きできます。書き込みアドレスとデータはAチャネルで送信されます。
  * アドレス0x38022010のEccMask0レジスタをデータ値0xffで設定します。
  * アドレス0x38022008のEccEidレジスタをデータ値0x4で設定します。
  * アドレス0x38022000のEccCtlレジスタをデータ値0x5で設定します。

![設定レジスタタイミング](./figure/DCache-Error-Config-Timing.svg){#fig:DCache-Error-Config-Timing width=80%}

### タグ注入タイミング

* 図\ref{fig:DCache-Error-TagInj-Timing}に示すように、レジスタ（EccCtl、EccEid、EccMask0）を設定すると、カウンタが0に到達した時点で注入が開始されます。

  * タグ注入インターフェース `io_pseudoError_0_valid` がアサートされます。

  * 注入が成功すると（`io_pseudoError_0_valid && io_pseudoError_0_ready == 1`）、EccCtl の `ese` ビットがクリアされ、注入が終了します。

  * MainPipe を例にとると、`s1_tag_error`、`s2_tag_error`、`s3_tag_error` が順にアサートされ、最終的に `io_error` ポート経由で BEU にエラー情報が報告されます。

![タグ注入タイミング](./figure/DCache-Error-TagInj-Timing.svg){#fig:DCache-Error-TagInj-Timing width=80%}

### データ注入タイミング

* 図\ref{fig:DCache-Error-DataInj-Timing}に示すように、レジスタ（EccCtl、EccEid、EccMask2）を設定すると、カウンタが0に到達した時点で注入が開始されます。

  * データ注入インターフェース `io_pseudoError_1_valid` がアサートされます。

  * 注入が成功すると（`io_pseudoError_1_valid && io_pseudoError_1_ready == 1`）、EccCtl の `ese` ビットがクリアされ、注入が終了します。

  * MainPipe を例にとると、`s2_data_error` と `s3_data_error` が順にアサートされ、最終的に `io_error` ポート経由で BEU にエラー情報が報告されます。

![データ注入タイミング](./figure/DCache-Error-DataInj-Timing.svg){#fig:DCache-Error-DataInj-Timing width=80%}
