# プローブキュー ProbeQueue

## 機能説明
L2からの一貫性要求を受信して処理を担当し、8つのProbeEntryを含み、それぞれが1つのプローブ要求を処理します。プローブ要求を内部信号に変換してMainPipeに送信し、MainPipeがプローブされたブロックの権限を変更します。MainPipeが応答を返すと、ProbeEntryは解放されます。

ProbeQueueは、チャネルBを介してL2とのみ対話し、MainPipeと相互接続します。内部的には、8つのProbeEntryアイテムで構成され、それぞれが要求信号の受信、変換、送信のための一連のステータスレジスタによって制御されます。

### 特徴1：エイリアシング問題

Kunminghuアーキテクチャは64KBのVIPTキャッシュを採用しており、キャッシュエイリアシングの問題が発生します。エイリアシングに対処するため、L2キャッシュディレクトリはDCacheに保存されている各物理ブロックのエイリアスビットを維持します。DCacheが物理アドレスで異なるエイリアスビットを持つブロックにアクセスしようとすると、L2キャッシュはプローブリクエストを開始して、DCacheから元のエイリアスブロックを追い出し、そのエイリアスビットをTileLink Bチャネルに記録します。リクエストを受信すると、ProbeQueueはエイリアスビットとページオフセットを連結し、内部信号に変換してMainPipeに送信します。MainPipeはDCacheストレージモジュールにアクセスしてデータを読み取ります。

### 特徴2：アトミック命令によるブロッキング

アトミック操作（lr-scを含む）はDCacheで完了するため、LR命令を実行するとき、ターゲットアドレスがすでにDCacheにあることを保証します。設計を簡素化するため、LR命令はMainPipeに予約セットを登録し、LRアドレスを記録してそのアドレスへのプローブをブロックします。デッドロックを回避するため、MainPipeはSC命令を一定期間待機した後、プローブのブロックを停止します（パラメータLRSCCyclesおよびLRSCBackOffによって決定されます）。この時点で、受信したSC命令はSC失敗と見なされます。したがって、LRによって予約セットが登録されてから一致するSCを待つまでの間、プローブリクエストはDCacheでの操作をブロックする必要があります。

## インターフェースタイミング
### リクエストインターフェースタイミングの例

[@fig:DCache-ProbeSnoop-Timing]は、プローブキューがプローブリクエストを処理する際のインターフェースタイミングを示しています。プローブキューはまずL2からプローブリクエストを受信し、それを内部リクエストに変換して空のProbeEntryを割り当てます。1サイクルの状態遷移の後、プローブリクエストをMainPipeに送信できます。ただし、タイミングの都合上、このリクエストはさらに1サイクル遅延されます（ProbeQueueでのエントリ選択にはアービタが関与し、MainPipeエントリにもさまざまなソースからのリクエストを選択するためのアービタがあるため、両方のアービトレーションを1サイクルで完了するのは困難です。したがって、ここでもう1サイクルのラッチングが行われます）。したがって、pipe_req_validは2サイクル後にアサートされます。その後、MainPipeの応答を受信すると、ProbeEntryは解放されます。

![ProbeSnoopタイミング](./figure/DCache-ProbeSnoop-Timing.png){#fig:DCache-ProbeSnoop-Timing}

## ProbeEntryモジュール

プローブエントリは一連のステータスレジスタによって制御され、ステートマシンがプローブトランザクションを実行します。[@tbl:ProbeEntry-state]は、各エントリに含まれる3つのステータスレジスタの意味を示しており、ステートマシンの設計は[@fig:DCache-ProbeEntry]に示されています。

Table: ProbeEntryステータスレジスタの説明 {#tbl:ProbeEntry-state}

| ステータス | 説明 |
| :--- | :--- |
| s_invalid | リセット状態：このプローブエントリは空です。 |
| s_pipe_req | プローブリクエストが割り当てられ、メインパイプリクエストを送信中 |
| s_wait_resp | メインパイプリクエストの送信が完了し、メインパイプの応答を待機中。 |
