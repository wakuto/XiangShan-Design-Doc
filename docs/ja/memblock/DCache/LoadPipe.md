# Loadメモリアクセスパイプライン LoadPipe

## 機能説明

パイプラインはLoadリクエストの処理を制御し、Loadメモリアクセスパイプラインと密接に結合しており、4ステージのパイプラインを通じてターゲットデータを読み出すか、miss/replay応答を返します。

### 特徴1：LoadPipeパイプラインステージの機能：

*   Stage 0: LoadUnit内のパイプラインで計算された仮想アドレスを受信し、アドレスに基づいてタグとメタを読み出します。
*   Stage 1: 対応するタグとメタのクエリ結果を取得し、LoadUnitから物理アドレスを受信して、タグ比較を行いヒットを判断します。アドレスに基づいてデータを読み出し、l2_errorをチェックします。
*   Stage 2: 対応するデータ結果を取得します。ロードミスが発生した場合、MissQueueにミスリクエストを送信し、MSHRエントリの割り当てを試みます。ロードリクエストに対する応答をLoadUnitに返します。tag_errorをチェックします。
*   Stage 3: 置換アルゴリズムの状態を更新し、バスエラーユニットに1ビットECCチェックエラーを報告します（dcacheが検出したデータエラー、dcacheが検出したタグエラー、L2からデータブロックを取得する際に既に存在していたエラーを含む）。

## インターフェースタイミング

### リクエストインターフェースタイミングの例

[@fig:DCache-LoadPipe-Timing]に示すように、req1は最初のサイクルでLoadPipeに受信され、メタとタグを読み出します。2番目のサイクルでタグ比較によりミスが判断されます。3番目のサイクルでLSUに応答が返され、lsu_resp_missがアサートされてヒットがなく、まだデータを返せないことを示し、同時にMissQueueにミスリクエストが送信されます。4番目のサイクルでECCエラーがあるかどうかをチェックして報告します。req2とreq3はreq1の直後に発行され、同様にstage_0で受信されてメタとタグを読み出します。2番目のサイクルでヒットが検出され、データ読み出しリクエストが発行されます。3番目のサイクルでデータが取得され、ロードデータ付きの応答がLSUに返されます。4番目のサイクルでPLRUが更新され、ECCエラーが報告されます。
