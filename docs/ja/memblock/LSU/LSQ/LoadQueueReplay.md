# Loadリプレイキュー LoadQueueReplay

## 機能説明

LoadQueueReplayは、リプレイが必要なロード命令を格納し、さまざまなウェイクアップ条件に基づいて命令をウェイクアップし、LoadUnitに実行をスケジュールするために使用されます。主に以下の状態と格納情報を含みます。

Table: LoadQueueReplay格納情報

| フィールド | 説明 |
| :--- | :--- |
| allocated | 割り当て済みかどうかを示し、エントリが有効かどうかも表します。 |
| scheduled | スケジュール済みかどうかを示し、アイテムがすでに選択され、リプレイのためにLoadUnitに送信済みまたは送信予定であることを示します。 |
| uop | Load命令の実行に含まれるuop情報。 |
| vecReplay | ベクトルロード命令関連情報 |
| vaddrModule | Load命令の仮想アドレス。 |
| cause | ロードリプレイキュー内のロード命令リプレイの理由。以下を含みます。 |
| | C_MA(ビット0): ストア-ロード予測違反 |
| | C_TM(ビット1): TLBミス |
| | C_FF(ビット2): ストアからロードへのフォワーディングでストアデータが準備できていないため失敗 |
| | C_DR(ビット3): DCacheミスが発生したが、MSHRを割り当てられない |
| | C_DM(ビット4): DCacheミスが発生 |
| | C_WF(ビット5): ウェイプレディクタの予測ミス |
| | C_BC(ビット6): バンクコンフリクト |
| | C_RAR(ビット7): LoadQueueRARに命令を受け入れるスペースがない |
| | C_RAW(ビット8): LoadQueueRAWに命令を受け入れるスペースがない |
| | C_NK(ビット9): LoadUnitがストアからロードへのフォワーディング違反を検出 |
| | C_MF(ビット10): LoadMisalignBufferに命令を受け入れるスペースがない |
| blocking | Load命令は現在ブロックされています。 |
| strict | メモリ依存性予測器が、命令がスケジューリングフェーズに入る前に先行するすべてのストア命令の実行完了を待つ必要があるかどうかを判断します。 |
| blockSqIdx | ロード命令に関連するストア命令のStoreQueueインデックス |
| missMSHRId | ロード命令のdcacheミスリクエスト受け入れID |
| tlbHintId | ロード命令のtlbミスリクエスト受け入れID |
| replacementUpdated | DCacheの置換アルゴリズムが更新されたかどうか |
| replayCarry | DCacheウェイプレディクタの予測情報 |
| missDbUpdated | ChiselDBでのミス関連の更新 |
| dataInLastBeatReg | Load命令が必要とするデータが2つのリフィルリクエストの最後のビートにある |

### 特徴1：順不同割り当て

*   ロードリクエストがLoadUnit S3に渡された後、まずエンキューが必要かどうかを判断する必要があります。リプレイが不要な場合、例外が発生した場合、またはリダイレクトによりフラッシュされた場合は、エンキューは不要です。LoadQueueReplayは、フリーリストを使用してキューの空きを管理します。フリーリストのサイズはロードリプレイキューのエントリ数と一致し、割り当て幅はロード幅（LoadUnitの数）に等しく、解放幅は4です。さらに、フリーリストはロードリプレイキューの残りのエントリと、それが満杯かどうかに関するフィードバックを提供します。LoadQueueReplayは、キューの空き管理にフリーリストを採用しています。フリーリストのサイズはLoadQueueReplayのエントリ数に対応し、割り当て幅はロード幅（LoadUnitの数）に等しく、解放幅は4です。

    *   割り当て
        *   LoadQueueReplayは、フリーリストの空きアイテム（図\ref{fig:LSQ-LoadQueueReplay-Freelist}の有効なアイテム）から各LoadUnitのエントリインデックスを選択します（空きアイテムのベストエフォート割り当て。たとえば、有効なアイテムが5と10で、LoadUnit0とLoadUnit2がアクティブな場合、LoadUnit0には5が割り当てられ、LoadUnit2には10が割り当てられます）。その後、命令情報はインデックスに基づいて対応するエントリに書き込まれます。

        ![フリーリスト](./figure/LSQ-LoadQueueReplay-Freelist.svg){#fig:LSQ-LoadQueueReplay-Freelist width=70%}

    *   回収
        *   正常にリプレイされた、またはフラッシュされたロード命令によって占有されていたエントリは、回収する必要があります。LoadQueueReplayは、ビットマップFreeMaskを使用して解放中のエントリを追跡し、フリーリストによってサイクルごとに最大4つのエントリが回収されます。

        ![フリーリストの回収](./figure/LSQ-LoadQueueReplay-Freelist-Recycle.svg){#fig:LSQ-LoadQueueReplay-Freelist-Recycle width=90%}

### 特徴2：ウェイクアップ

*   ブロッキング条件が異なれば、ウェイクアップ条件も異なります。

    *   C_MA：strict==1の場合、Load命令は先行するすべてのストア命令のアドレス計算が完了するまで待ってからウェイクアップする必要があります。それ以外の場合は、blockSqIdxに対応するストア命令のアドレス計算が完了するのを待つだけで済みます。

    *   C_TM：TLBにミスリクエストを処理する余分なスペースがない場合、リプレイ準備完了としてマークされ、スケジューリングを待つことができます。それ以外の場合は、tlbHintIdに一致するヒント信号をTLBが返すのを待ってウェイクアップする必要があります。

    *   C_FF：ウェイクアップする前に、blockSqIdxに対応するストア命令のデータが準備できるまで待つ必要があります。

    *   C_DR：リプレイ準備完了としてマークされ、スケジューリングを待つことができます。

    *   C_DM：missMSHRIdに一致するL2ヒント信号を待ってウェイクアップします。

    *   C_WF：リプレイ準備完了としてマークされ、スケジューリングを待つことができます。

    *   C_BC：リプレイ準備完了状態としてマークされ、スケジューリングを待つことができます。

    *   C_RAR：LoadQueueRARに空きスペースがある場合、または命令が最も古いロード命令である場合にウェイクアップできます。

    *   C_RAW：LoadQueueRAWに空きスペースがあるか、先行するすべてのストア命令のアドレス計算が完了した後に、ロード命令をウェイクアップできます。

    *   C_MF：ウェイクアップされる前に、LoadMisalignBufferに空きスペースができるのを待ちます。

### 特徴3：選択的スケジューリング

*   LoadQueueReplayには3つの選択的スケジューリング方法があります。

    *   エンキュー年齢に基づく
        *   LoadQueueReplayは3つの年齢マトリックス（各バンクに1つ）を使用してエンキュー時間を記録します。年齢マトリックスは、リプレイ準備が整った命令の中から最も長くエンキューされている命令を選択し、再送のためにスケジュールします。

    *   Load命令の年齢に基づく
        *   LoadQueueReplayは、LqPtrに基づいてリプレイする最も古いLoad命令を決定でき、選択幅はOldestSelectStride=4です。

    *   DCacheデータ関連のロード命令を優先的にスケジューリング
        *   LoadQueueReplyは、まずL2ヒントによってトリガーされたリプレイをスケジュールします（dcacheミスが発生した場合、下位レベルのキャッシュL2をクエリし続ける必要があります。L2キャッシュがリフィルする2〜3サイクル前に、L2キャッシュはLoadQueueReplayに早期ウェイクアップ信号を送信します。これはL2ヒントとして知られています）。L2ヒントを受信すると、LoadQueueReplayはdcacheミスによってブロックされたLoad命令をより早くウェイクアップしてリプレイできます。

        *   L2ヒントのシナリオがない場合、ロードリプレイの残りの理由は高優先度と低優先度に分類されます。高優先度には、dcacheミスまたはst-ldフォワーディングによるリプレイが含まれ、他の理由は低優先度に分類されます。LoadQueueReplayからリプレイ条件を満たすLoad命令（有効、未スケジュール、かつウェイクアップを待機してブロックされていない）を見つけることができれば、そのLoad命令がリプレイのために選択されます。それ以外の場合は、エンキュー順に従って、AgeDetectorモジュールを介して一連のロードリプレイキューエントリの中で最も早くエンキューされたものを見つけてリプレイします。
