# 書込み後読出し違反チェック LoadQueueRAW

## 機能説明

LoadQueueRAWは、ストア-ロード違反を処理するために設計されています。ロードとストアはパイプライン内で順序不同に実行されるため、ロードが同じアドレスへの古いストアをバイパスすることがよくあります。このロードはストアからデータを転送すべきでしたが、ストアのアドレスまたはデータが準備できていない場合、ロードはストアのデータを転送せずにコミットされる可能性があります。その後、ロードの結果を使用する後続の命令は不正になり、ストアからロードへの転送違反が発生します。

ストアアドレスがSTA予約ステーションから発行され、ストアパイプラインに入ると、このストアの後にあり、同じアドレスを持つ完了したすべてのロードについてLQRAWを照会し、また、現在実行中で、このストアの後にあり、同じアドレスを持つロードパイプライン内のロードも照会します。いずれかが見つかった場合、ストアからロードへの転送違反が発生します。複数の違反ロードが存在する可能性があり、最も古い違反ロード（つまり、ストアに最も近いもの）を特定する必要があります。その後、リダイレクト要求がRedirectGeneratorコンポーネントに送信され、最も古い違反ロードとその後続のすべての命令がフラッシュされます。

ストアパイプラインがcbo zero命令を実行する場合も、ストア-ロード違反チェックが必要です。

### 特性1：ロードクエリのエンキュー

クエリがロードパイプラインのS2ステージに到達すると、エンキュー条件が満たされているかどうかが判断されます。現在のロード命令の前にアドレスが準備できていないストア命令があり、現在の命令がフラッシュされていない場合、現在のロードをエンキューできます。

フリーリストから割り当て可能なエントリとそのインデックスを取得します。

エンキューされたクエリの物理アドレスは24ビットに圧縮され、PaddrModuleの対応するエントリに格納されます。

エンキューされたクエリのマスクは、maskModuleの対応するエントリに格納されます。

### 特性2：ストア-ロード違反チェック

ストア命令がストアパイプラインのステージs1に到達すると、ストア-ロードチェックが実行されます。ストアは、メモリアクセスを完了したLoadQueueRAW内のロード、および現在メモリアクセス中のロードパイプラインのステージs1およびs2のロードと比較されます。これらのロードは、ストアからデータを転送していない可能性があります。チェックにより、ロードとストアの間に重複する物理アドレスが明らかになり、ロードがストアより新しい場合、違反が発生します。最も古いロードを特定し、このロードとその後続のすべての命令を再発行（再フェッチおよび再実行）する必要があります。ストア-ロード違反チェックの結果は、ストアパイプラインのステージs4で取得されます。

このプロセスは4つのサイクルに分かれています。

* 最初のサイクルでは、物理アドレスのマッチングと条件のマッチングが実行され、マスクが生成されます。これは、ストアの後に発生する新しいロードに一致します。これらのロードがすでにデータを取得している（datavalid）か、dcacheミスが発生してリフィルを待っている（miss）場合、それらは間違いなくこのストアからデータを転送していません。
* ストアパイプラインの2番目のサイクルでは、ストア操作はマスクに基づいてLoadQueueRAW内の一致するすべてのロードを識別します。LoadQueueRAWには合計32のエントリがあり、それぞれ4つのエントリからなる8つのグループに分かれています。各グループから、最も古いエントリが選択され、最大で4つの最も古いエントリが生成される可能性があります。
* 3番目のサイクルでは、4つの最も古い候補から最も古いエントリが選択されます。
* 4番目のサイクルでは、ストアパイプラインの両方のストアがストアからロードへの違反をトリガーした場合、各パイプラインからロードキューで一致した2つの最も古いロードのうち古い方が選択され、リダイレクトにロールバック要求が送信されます。

## インターフェースタイミング

### LoadQueueRAWエンキュー要求タイミングの例

![LoadQueueRAWエンキュー要求タイミング](./figure/LoadQueueRAW-enqueue.svg){#fig:RAW-enqueue width=70%}

io_query_*_req_validとio_query_*_req_readyの両方がハイの場合、ハンドシェイクが成功したことを示します。needEnqueueとio_canAllocate_*の両方がハイの場合、io_doAllocate_*がハイに設定され、クエリをエンキューする必要があり、FreeListが割り当て可能であることを示します。io_allocateSlot_*は、エンキューされたクエリを受信するエントリを表します。次のサイクルで、対応するエントリのallocate信号が立ち上がり、sqIdxがエントリに書き込まれます。その後のサイクルで、マスクがLqMaskModuleの対応するエントリに書き込まれ、圧縮された物理アドレスがLqPAddrModuleの対応するエントリに書き込まれます。

### ストア-ロード違反タイミングの例

![ストア-ロード違反チェックタイミング](./figure/LoadQueueRAW-store-to-load.svg){#fig:RAW-store-to-load width=70%}

io_rollback_validがハイの場合、ストア-ロード違反が発生したことを示し、違反の詳細はio_rollback_bits_*によって提供されます。
